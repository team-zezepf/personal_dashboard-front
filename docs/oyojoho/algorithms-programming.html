アルゴリズムとプログラミングのまとめ

計算量(オーダー記法)と整列アルゴリズムの安定性、スタック・キューを用いたグラフ探索(深さ優先探索・幅優先探索)、再帰処理の呼び出し回数トレースと動的計画法、ハッシュ法における衝突など、応用情報技術者試験のアルゴリズムとプログラミングで問われる、基本情報技術者試験より一段深いトレース・比較の視点を扱います。読み終えたら下部から問題を解いて定着させましょう。

1計算量(オーダー記法)と整列・探索アルゴリズムの比較

アルゴリズムの効率を表す指標であるオーダー記法(O記法)は基本情報技術者試験でも扱われるが、応用情報技術者試験ではさらに、平均計算量と最悪計算量の違い、ピボットの選び方によって性能が変化する理由、整列アルゴリズムの「安定性」まで踏み込んで問われる。

計算量(オーダー記法)の大小関係 処理時間の増加が緩やかな順に並べると次のようになる。
O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2ⁿ)
応用情報技術者試験では、O(n log n)とO(n²)の使い分けに加え、単純な再帰などに現れるO(2ⁿ)(指数的な計算量)を見分けられるかも問われる。
探索アルゴリズム前提条件計算量
線形探索特になし(未整列でもよい)O(n)
二分探索データが整列済みであることO(log n)
例題: 二分探索のトレースとO(log n)の意味 整列済み配列 [2, 9, 14, 21, 30, 38, 45, 53, 61](要素数9、添字0〜8)から 61 を探す。
①中央(添字4)の30と比較→61は30より大きいので右側(添字5〜8)
②中央(添字6)の45と比較→61は45より大きいので右側(添字7〜8)
③中央(添字7)の53と比較→61は53より大きいので右側(添字8)
④添字8の61と比較→一致
合計4回の比較で発見できる。要素数nに対する比較回数の上限は⌈log2 n⌉程度に収まる(n=9なら⌈log2 9⌉=4)。これがO(log n)と呼ばれる理由であり、nが2倍になっても比較回数は高々1回程度しか増えない点が、O(n)である線形探索との決定的な違いである。
整列アルゴリズム平均計算量最悪計算量安定性
バブルソートO(n²)O(n²)安定
選択ソートO(n²)O(n²)不安定
クイックソートO(n log n)O(n²)不安定(実装による)
マージソートO(n log n)O(n log n)安定
例題: クイックソートが最悪計算量O(n²)になるケース 先頭要素を常にピボットに選ぶ実装で、既に昇順に整列済みの配列 [1, 2, 3, 4, 5] を整列する場合を考える。
①ピボット1を選択→1より小さい要素なし、大きい要素は[2,3,4,5]の4個。比較4回
②残り[2,3,4,5]でピボット2を選択→比較3回
③残り[3,4,5]でピボット3を選択→比較2回
④残り[4,5]でピボット4を選択→比較1回
比較回数の合計は4+3+2+1=10回で、要素数n=5に対しおよそn(n-1)/2に相当するO(n²)となる。データが「1個」と「残り全部」に毎回偏って分割されてしまうことが原因であり、これがクイックソートの最悪ケースである。
例題: 安定性の確認 (山田, 70点)→(佐藤, 70点)→(鈴木, 90点) の順に並んだデータを、得点の昇順に整列する場合を考える。安定なソート(バブルソート、マージソートなど)では、同点(70点)の山田と佐藤の並び順は整列後も入力時と同じ「山田→佐藤」のまま保たれる。
これに対し不安定なソート(選択ソートや一般的なクイックソートなど)では、内部での要素の交換方法によって同点データの順序が「佐藤→山田」のように入れ替わってしまうことがある。
つまずきやすいポイント 「平均計算量」と「最悪計算量」は区別して覚える。クイックソートは平均O(n log n)だが、ピボットの選び方(特に整列済みに近いデータで先頭や末尾を選ぶ場合)によって最悪O(n²)に悪化する。また、整列アルゴリズムの「安定性」は計算量とは別の観点であり、クイックソートとマージソートのように同じO(n log n)でも安定性が異なる場合がある点に注意する。
練習問題 0 / 2問 正解

問1　同じキーを持つデータの元の並び順が、整列後も保たれる(安定な)整列アルゴリズムの組合せはどれか。

バブルソートは隣り合う要素だけを交換し、マージソートは併合のときに同じキーなら前半の要素を先に取るので、どちらも安定。選択ソートは離れた位置の要素と交換するため、クイックソートは分割の際に要素を大きく移動させるため、一般に不安定。

問2　先頭の要素を常にピボットに選ぶクイックソートで、計算量が O(n²) になる入力はどれか。

整列済みの配列では、ピボット(先頭の最小値)より小さい要素がなく、分割のたびに「0個」と「残り全部」に分かれる。そのため分割が n 回近く続き、比較回数は n²/2 程度になる。ランダムな配列ならおおむね半分ずつに分かれ、平均 O(n log n) になる。

2スタックとキューを用いた操作のトレース

スタック(LIFO: Last In First Out)とキュー(FIFO: First In First Out)は基本情報技術者試験でも問われる基礎知識だが、応用情報技術者試験ではpushとpop、あるいはenqueueとdequeueが入り交じった一連の操作をトレースし、各操作で「何が取り出されるか」「最終的にデータ構造内に何が残るか」を正確に追跡する力が問われる。

例題: push/popが混在する操作のトレース push(A), push(B), pop(), push(C), push(D), pop(), pop() の順に操作したときの、各popで取り出される値と最終的なスタックの中身を追跡する。
push(A): スタック[A]
push(B): スタック[A, B]
pop()→Bを取り出す: スタック[A]
push(C): スタック[A, C]
push(D): スタック[A, C, D]
pop()→Dを取り出す: スタック[A, C]
pop()→Cを取り出す: スタック[A]
取り出された順序はB, D, C。最終的にスタックに残るのはAのみである。
例題: enqueue/dequeueが混在する操作のトレース enqueue(A), enqueue(B), dequeue(), enqueue(C), dequeue(), dequeue() の順に操作する。
enqueue(A): キュー[A]
enqueue(B): キュー[A, B]
dequeue()→Aを取り出す: キュー[B]
enqueue(C): キュー[B, C]
dequeue()→Bを取り出す: キュー[C]
dequeue()→Cを取り出す: キュー[]
取り出された順序はA, B, Cで、追加した順序と完全に一致する(先入れ先出し)。スタックの例(B, D, C)と対比すると、操作が入り交じってもキューは追加順を維持する点が特徴である。
つまずきやすいポイント スタック・キューが混在するトレース問題では、操作の順序を1つずつ丁寧に書き出さないと、途中でpush/pop(あるいはenqueue/dequeue)の対象を取り違えやすい。特にpop・dequeueの直後にpush・enqueueが続く場合、「今、中に何が残っているか」を毎回書き出して確認するとよい。
練習問題 0 / 2問 正解

問1　空のスタックに対して push(1)、push(2)、push(3)、pop()、pop()、push(4)、pop()、push(5) の順に操作した。最終的にスタックに残っている要素を、底から順に並べたものはどれか。

1, 2, 3 を積んだ後、pop で 3、pop で 2 が取り出され [1]。4 を積んで pop で 4 が取り出され [1]。最後に 5 を積むので [1, 5]。アは最後の pop で 4 が残ると考えた場合。

問2　空のキューに A、B、C の順に enqueue し、続いて dequeue で取り出したものを順に空のスタックへ push した。その後、スタックから pop を3回行ったとき、取り出される順はどれか。

キューは先入れ先出しなので、dequeue で A、B、C の順に取り出され、その順にスタックへ push される。スタックは後入れ先出しなので、pop すると C、B、A の順に出る。キューとスタックを組み合わせると、並びが逆順になる。

3グラフの探索(深さ優先探索・幅優先探索)

グラフ(木構造を含む)を探索するアルゴリズムの代表例として、深さ優先探索(DFS: Depth-First Search)と幅優先探索(BFS: Breadth-First Search)がある。DFSはスタック(または再帰呼び出し)を用いて1つの経路を行き止まりまで進んでから後戻りするのに対し、BFSはキューを用いて根に近い頂点から順に探索する。

例題: 深さ優先探索(DFS)のトレース(スタックを使用) 上図のグラフに対し、根Aからスタックを用いてDFSを行う(左の子から先に訪問されるよう、子は右から順にpushする)。
①Aをpush→pop・訪問。子C, Bの順でpush→スタック[C, B]
②Bをpop・訪問。子E, Dの順でpush→スタック[C, E, D]
③Dをpop・訪問(子なし)→スタック[C, E]
④Eをpop・訪問(子なし)→スタック[C]
⑤Cをpop・訪問。子Fをpush→スタック[F]
⑥Fをpop・訪問(子なし)→スタック[]
訪問順序はA→B→D→E→C→Fとなる。
例題: 幅優先探索(BFS)のトレース(キューを使用) 同じグラフに対し、根Aからキューを用いてBFSを行う。
①Aをenqueue→dequeue・訪問。子B, Cをenqueue→キュー[B, C]
②Bをdequeue・訪問。子D, Eをenqueue→キュー[C, D, E]
③Cをdequeue・訪問。子Fをenqueue→キュー[D, E, F]
④D, E, Fの順にdequeue・訪問(いずれも子なし)
訪問順序はA→B→C→D→E→Fとなり、根に近い階層(レベル)から順に訪問される。
探索方法用いるデータ構造訪問順序の特徴主な用途
深さ優先探索(DFS)スタック(または再帰)1つの経路を行き止まりまで進んでから後戻りする迷路の探索、一筆書き問題、経路の全列挙
幅優先探索(BFS)キュー根に近い頂点から階層(レベル)順に探索する重みなしグラフでの最短経路探索
つまずきやすいポイント DFSは経路を深く進むため目的の頂点を偶然早く見つけることもあるが、最短経路(最少の辺数)を保証しない。重みのないグラフで最短経路を求めたい場合はBFSを用いる必要がある。「スタックを使う・再帰を使う→DFS」「キューを使う→BFS」という対応を覚えておくと、問題文からどちらの探索かを素早く判別できる。
練習問題 0 / 2問 正解

問1　根 A の子が B と C、B の子が D と E、C の子が F と G である木を、A から幅優先探索する。訪問する順はどれか(同じ親の子は左から訪問する)。

幅優先探索はキューを使い、根に近い階層から順に訪問するので A → B, C → D, E, F, G。アは1つの経路を奥まで進む深さ優先探索(行きがけ順)の訪問順、イは帰りがけ順。

問2　辺に重みのないグラフで、始点から目的の頂点まで最少の辺数で到達する経路を求めたい。適した探索方法と、用いるデータ構造の組合せはどれか。

幅優先探索はキューを使って始点に近い頂点から順に調べるので、最初に見つけた経路が最少の辺数になる。深さ優先探索(スタックまたは再帰)は目的の頂点を早く見つけることもあるが、最短経路は保証しない。

4再帰処理のトレースと動的計画法

サブルーチンが自分自身を呼び出す再帰は基本情報技術者試験でも扱われるが、応用情報技術者試験では「合計で何回呼び出されるか」「どのタイミングで計算が確定するか」といった、より詳細なトレースが求められる。また、同じ引数の呼び出しが何度も発生し非効率になる再帰を改善する動的計画法も重要な出題テーマである。

例題: 再帰呼び出しの回数を数える fact(n)を「n>0ならばn×fact(n-1)、n=0ならば1」と定義する(基底条件はfact(0))。fact(4)を呼び出したときの、fact(4)自身を含めた呼び出し回数を考える。
fact(4) → fact(3)を呼び出す(1回目)
fact(3) → fact(2)を呼び出す(2回目)
fact(2) → fact(1)を呼び出す(3回目)
fact(1) → fact(0)を呼び出す(4回目)
fact(0)は基底条件なのでこれ以上呼び出さない(5回目、ここでカウント終了)
呼び出し回数はfact(4)自身を含めて5回(fact(4), fact(3), fact(2), fact(1), fact(0)の5つ)。戻りながら計算すると fact(0)=1 → fact(1)=1×1=1 → fact(2)=2×1=2 → fact(3)=3×2=6 → fact(4)=4×6=24。
つまずきやすいポイント 呼び出し回数を数える際、「fact(4)自身を含めるか」「基底条件(fact(0))の呼び出しを1回として数えるか」を見落として1回分ずれやすい。fact(n)の呼び出し回数は、基底条件も含めてn+1回(fact(n), fact(n-1), …, fact(0))になる点を押さえておくとよい。

再帰は簡潔に書ける一方、フィボナッチ数列のように1つ前だけでなく複数手前の値を必要とする再帰では、同じ引数の呼び出しが何度も重複して発生し、呼び出し回数が指数的に増大してしまう問題がある。

例題: フィボナッチ数列の単純な再帰呼び出しのトレース fib(n) = fib(n-1) + fib(n-2)(n≧2)、fib(0)=0, fib(1)=1 と定義する。fib(4)を単純に再帰で計算すると、呼び出しの様子は次のようになる。
fib(4)
  ├─ fib(3)
  │   ├─ fib(2)
  │   │   ├─ fib(1)
  │   │   └─ fib(0)
  │   └─ fib(1)
  └─ fib(2)
     ├─ fib(1)
     └─ fib(0)
この呼び出し木の中でfib(2)は2回、fib(1)は3回、fib(0)は2回、それぞれ同じ引数で重複して計算されており、呼び出し総数は9回にのぼる。nが大きくなるほどこの重複は加速度的に増え、計算量はおよそO(2ⁿ)という指数関数的なオーダーになる。
手法fib(4)の呼び出し回数計算量(概算)特徴
単純な再帰9回O(2ⁿ)同じ引数の呼び出しを何度も重複して計算する
動的計画法(メモ化)5回(fib(0)〜fib(4)を1回ずつ)O(n)一度計算した部分問題の結果を配列などに保存し、再利用する
つまずきやすいポイント 動的計画法は「漸化式を立てて再帰的に解く」点は単純な再帰と同じだが、計算結果をメモ化(表に保存)して再利用する点が異なる。マージソートのような分割統治法も問題を分割して再帰的に解くが、部分問題同士に重なりがなく使い回す必要がない点で動的計画法とは異なる。両者を混同しないよう注意する。
練習問題 0 / 2問 正解

問1　fib(n) を「n ≧ 2 なら fib(n − 1) + fib(n − 2)、fib(0) = 0、fib(1) = 1」と定義し、単純な再帰で計算する。fib(5) を呼び出したとき、fib(5) 自身を含めた呼び出し回数はどれか。

fib(n) の呼び出し回数を C(n) とすると、C(0) = C(1) = 1、C(n) = 1 + C(n − 1) + C(n − 2)。C(2) = 3、C(3) = 5、C(4) = 9、C(5) = 1 + 9 + 5 = 15。イは fib(4) の場合の回数。アは fib(0)〜fib(5) を1回ずつ呼ぶ動的計画法(メモ化)の場合。エは fib(5) の値そのもの。

問2　動的計画法の説明として、適切なものはどれか。

動的計画法は、部分問題の結果を保存(メモ化)して再利用することで、単純な再帰で起きる同じ引数の重複計算をなくす。フィボナッチ数列では計算量が O(2ⁿ) から O(n) に下がる。基底条件のない再帰は終わらない(ウ)。

5ハッシュ法とキーの衝突(シノニム)

ハッシュ法は、キーの値から一定の計算(ハッシュ関数)によって格納位置(アドレス)を直接求めることで、平均的にO(1)という高速なデータアクセスを実現する格納・探索方式である。代表的なハッシュ関数として、キーを表の大きさで割った余りを用いる剰余法(除算法)がある。

例題: ハッシュ関数による格納と衝突(シノニム)の発生 表の大きさm=7、ハッシュ関数h(k)=k mod 7として、キー10, 15, 21, 24をこの順に格納する。
h(10)=10 mod 7=3 → 添字3に格納
h(15)=15 mod 7=1 → 添字1に格納
h(21)=21 mod 7=0 → 添字0に格納
h(24)=24 mod 7=3 → 添字3には既に10が格納済みのため衝突(シノニム)が発生する
このように異なるキー(10と24)のハッシュ値が一致してしまう現象を衝突またはシノニムと呼び、何らかの方法で解決する必要がある。
衝突解決法説明
チェイン法(連鎖法)同じハッシュ値を持つデータを線形リストなどで連結して格納する(上図の10→24のように、衝突したデータを鎖状につなげる)
オープンアドレス法(線形探査法など)衝突が起きた場合、あらかじめ定めた規則(例: 次の空き番地を順に探す)に従って別の格納場所を探す
つまずきやすいポイント ハッシュ法は平均的にはO(1)で高速だが、衝突が多発する(データ件数が表の大きさに対して多い、ハッシュ関数の分布が偏っている等)と衝突解決のための探索が発生し、最悪の場合は線形探索に近いO(n)まで性能が低下する。「ハッシュ法は常にO(1)」と単純に覚えず、衝突の発生しやすさ(表の大きさとデータ件数の比率=充填率)が性能に影響する点を押さえておく。
練習問題 0 / 2問 正解

問1　大きさ11のハッシュ表に、ハッシュ関数 h(k) = k mod 11 でキー 15、26、30、41 をこの順に格納する。衝突したときは次の番地(+1)から空きを探すオープンアドレス法(線形探査)を使う。キー 41 が格納される番地はどれか。

h(15) = 4 で4番地、h(26) = 4 は衝突するので5番地、h(30) = 8 で8番地。h(41) = 8 は30と衝突するので、次の9番地に格納される。アは衝突を考えずにハッシュ値をそのまま使った場合。

問2　ハッシュ法の衝突解決法のうち、チェイン法(連鎖法)の説明として、適切なものはどれか。

チェイン法は、同じ番地に属するデータを鎖状につないでおく。アはオープンアドレス法(線形探査法)の説明。どちらの方法でも、衝突が多くなると探索が遅くなり、平均 O(1) の速さが失われる。
