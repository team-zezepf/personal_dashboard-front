ソフトウェアのまとめ

CPUスケジューリングの各方式の違い、仮想記憶(ページング方式)とガベージコレクションによるメモリ管理、複数プロセスが資源待ちで停止するデッドロックなど、応用情報ではOSの内部動作をより踏み込んで問われる。読み終えたら下部から問題を解いて定着させましょう。

1CPUスケジューリング方式

マルチタスクOSは、実行可能な複数のプロセスに対してCPUの使用権(タイムスライス)をどの順序・条件で割り当てるかを決めるスケジューリング方式を持つ。基本情報では「タスク管理がCPU時間を割り当てる」という役割理解が中心だったのに対し、応用情報では各方式の割り当てルールの違いや、方式によって生じる有利・不利な条件までを見分ける力が問われる。

方式割り当てルール特徴
FCFS(到着順)到着した順にCPUを割り当てる実装は単純だが、先着の処理時間が長いと後続が長時間待たされる(コンボイ効果)
SJF(最短時間優先)実行時間が最も短いプロセスを優先する平均待ち時間は短縮できるが、実行時間の長いプロセスが待たされ続ける可能性がある(飢餓)
優先度順プロセスごとに設定された優先度の高い順に割り当てる優先度の低いプロセスがいつまでも実行されない可能性がある
ラウンドロビン一定時間(タイムクウォンタム)ごとに、実行可能プロセスへ順番にCPUを割り当てる各プロセスが均等にCPUを得られるため公平性が高く、対話型システムに向く
例題: ラウンドロビン方式でのCPU割り当てを追跡する タイムクウォンタムを2、実行可能プロセスをA→B→Cの順で並んだキューとし、各プロセスの残り実行時間をA=3、B=1、C=2とする。
①A(2消費・残り1)→②B(1消費で完了・残り0)→③C(2消費で完了・残り0)→④A(残り1を消費して完了)、の順でCPUが割り当てられる。B・Cのように残り時間がタイムクウォンタム以下のプロセスはその時点で処理が完了し、キューから外れる。Aのように使い切れなかったプロセスは、キューの末尾に再度並んで次の順番を待つ。
つまずきやすいポイント ラウンドロビンは「時間(タイムクウォンタム)」で区切って強制的にCPUを切り替える方式であるのに対し、優先度順は「優先度」を基準に(優先度の高いプロセスが到着すれば実行中のプロセスを中断して)CPUを渡す方式である。どちらも実行中のプロセスからCPUを奪う点(プリエンプティブ)は共通するが、切り替えの判断基準が「時間」か「優先度」かを取り違えないこと。
練習問題 0 / 2問 正解

問1　タイムクウォンタムを2とするラウンドロビン方式で、実行可能キューに A、B、C の順に並んでいる。残りの実行時間は A = 3、B = 4、C = 1 である。処理が完了する順はどれか(新たなプロセスの到着や入出力待ちはないものとする)。

A が2使って残り1でキューの最後尾へ、B が2使って残り2で最後尾へ、C が1使って完了(時刻5)。続いて A が残り1を使って完了(時刻6)、B が残り2を使って完了(時刻8)。完了順は C、A、B。アは到着順(FCFS)で処理した場合。

問2　実行時間が最も短いプロセスを優先するSJF(最短時間優先)方式の問題点として、適切なものはどれか。

SJFは平均待ち時間を短くできるが、短いプロセスが次々に来ると長いプロセスが後回しにされ続ける。イはFCFS(到着順)のコンボイ効果、エはラウンドロビンの欠点。SJFの平均待ち時間はむしろ短い(アは誤り)。

2仮想記憶(ページング方式)とガベージコレクション

ページング方式は、仮想記憶を固定長の「ページ」単位に分割して管理する方式である。プログラム全体を主記憶に載せるのではなく、実行に必要なページだけをそのつど主記憶に読み込む(デマンドページング)ことで、実際の主記憶容量よりも大きい仮想アドレス空間を扱えるようにする。

例題: ページフォールト発生時の処理の流れ ①CPUが論理アドレスを参照する。②ページテーブルを引き、対象ページが主記憶上に存在するか(不在ビット)を確認する。③不在であればページフォールトが発生し、CPUの制御がOSに移る。④OSは補助記憶装置から該当ページを主記憶の空き枠(または追い出し対象の枠)に読み込み、ページテーブルを更新する。⑤中断していた命令を再実行する。
このように、ページフォールトは「エラー」ではなく、仮想記憶を実現するための正常な仕組みの一部である点に注意する。

一方、ガベージコレクションは、プログラム実行中にヒープ上へ動的に確保されたメモリ領域のうち、どこからも参照されなくなった(不要になった)領域を実行時に自動的に検出・解放する仕組みである。JavaやC#などの言語処理系のランタイムに組み込まれており、プログラマがC言語のfree()のように明示的に解放処理を書かなくても、メモリリークを防ぎやすくなる。

仕組み管理の対象目的
ページング方式(仮想記憶)プロセスに割り当てる主記憶・補助記憶の領域(ページ単位)実メモリより大きいアドレス空間を、必要な部分だけロードして扱えるようにする
ガベージコレクションプログラムがヒープ上に動的確保したオブジェクト不要になった領域を自動検出・解放し、メモリリークを防ぐ
つまずきやすいポイント ページングとガベージコレクションはどちらも「メモリに関する自動化された仕組み」だが、層が異なる。ページングはOSがプロセス単位のアドレス空間を主記憶・補助記憶の間で管理する仕組みであり、ガベージコレクションは言語処理系(ランタイム)がプログラム内のオブジェクト単位で参照の有無を判定し解放する仕組みである。また、デフラグメンテーション(断片化の解消)やキャッシング(高速化)は目的も対象も異なるため、「メモリ関連の自動処理」という表面的な共通点だけで混同しないこと。
練習問題 0 / 2問 正解

問1　プログラムの実行中にヒープ上へ動的に確保された領域のうち、どこからも参照されなくなったものを自動的に検出して解放する仕組みはどれか。

ガベージコレクションは、プログラムが確保したオブジェクトの不要な領域を解放し、メモリリークを防ぐ。ページングとスワッピングは、OSがプロセス単位で主記憶と補助記憶の間でデータを入れ替える仕組みで、管理する層が異なる。

問2　ページング方式の仮想記憶で、ページフォールトが発生したときの処理として、適切なものはどれか。

ページフォールトは、参照したページが主記憶上にない(不在)ときに起きる割り込み。OSが補助記憶から読み込み(空きがなければページ置換を行い)、ページテーブルを更新して、中断した命令から処理を再開する。異常終了ではない。

3デッドロック

デッドロックとは、複数のプロセスがそれぞれ相手の占有する資源の解放を待ち合い、どのプロセスも処理を先に進められなくなる状態である。プロセスが停止しているように見える点でスラッシング(ページングが多発し性能が著しく低下する現象)と混同されやすいが、原因も状態も異なる。

例題: デッドロックが発生する典型的なシナリオ プロセスXは資源Aをロック済みで資源Bの解放を待っており、同時にプロセスYは資源Bをロック済みで資源Aの解放を待っているとする。この場合、XはYが資源Bを解放するのを待ち、YはXが資源Aを解放するのを待つため、双方とも永久に待ち続けることになる。これは、2つのプロセスが資源を確保する順序が逆になっていることが原因であり、資源を確保する順序を全プロセスで統一する(例えば必ずA→Bの順で確保する)ことで、このような循環待ちを防止できる。
つまずきやすいポイント デッドロックは「資源の奪い合いによる待ち合い」で処理が完全に停止する状態であるのに対し、スラッシングは「主記憶が不足し、ページの入れ替え(スワッピング)が頻発することでCPUがページング処理に時間を取られ、実質的な処理効率が著しく低下する」現象である。どちらも「システムが遅い・進まない」という結果は似て見えるが、原因が資源の相互待ち(デッドロック)か、主記憶不足によるページ入れ替えの多発(スラッシング)かという点で区別する。
練習問題 0 / 2問 正解

問1　デッドロックの発生を防ぐ方法として、適切なものはどれか。

資源を確保する順序をそろえると、「Xが資源Aを持ってBを待ち、YがBを持ってAを待つ」という循環した待ち合いが起きなくなる。タイムクウォンタムや優先度を変えても、資源の待ち合いは解消しない。主記憶の増設はスラッシングの対策。

問2　主記憶が不足してページの入れ替えが頻繁に起こり、その処理に時間を取られてシステムの処理がほとんど進まなくなる状態はどれか。

スラッシングはページの入れ替えの多発で性能が極端に落ちる状態。デッドロックは資源の待ち合いで処理が完全に止まる状態。ページフォールトは参照したページが主記憶にないこと(1回1回の事象)で、それが多発するとスラッシングになる。
