ネットワークのまとめ

応用情報技術者試験のネットワーク分野では、基本情報の知識を前提に、サブネット計算やルーティングプロトコルの選定、TCP/ARP/DNSといったプロトコルの詳細な動作、NAT・TLSなどの実務的な技術がより深く問われる。計算問題と仕組みの理解の両方を押さえておくことが重要である。

1ネットワーク層とルーティングプロトコル

OSI基本参照モデルの第3層である「ネットワーク層」は、IPアドレスをもとに送信元から宛先までの通信経路を選択する「ルーティング(経路制御)」を担う層である。基本情報では各層の名称と役割を覚えることが中心だったが、応用情報ではルータがどのようにルーティングを行うか、その裏側にある「ルーティングプロトコル」の仕組みまで問われる。

プロトコル方式使用範囲メトリック(経路選択の基準)
RIP距離ベクトル型(ベルマンフォード法)AS内(IGP)ホップ数(最大15)
OSPFリンクステート型(ダイクストラ法)AS内(IGP)帯域幅等から算出したコスト
BGPパスベクトル型AS間(EGP)経由する自律システム(AS)の数など

RIPはホップ数(経由するルータの数)のみを基準に経路を選ぶ単純な方式であるため、帯域幅の違いを考慮できず、大規模なネットワークには不向きである。OSPFはリンクごとのコストを考慮できるため、より効率的な経路選択が可能であり、企業内ネットワークなどのAS(自律システム)内で広く使われる。BGPはインターネット全体のようにAS同士を接続する場面で使われ、単純な最短経路ではなく経路制御のポリシーを重視する点が特徴である。

つまずきやすいポイント 「リンクステート型(OSPF)」と「距離ベクトル型(RIP)」の違いは頻出である。距離ベクトル型は隣接ルータから伝え聞いた距離情報だけを頼りに経路を決めるのに対し、リンクステート型は各ルータがネットワーク全体のリンク情報を共有したうえで最短経路を計算する点で異なる。また、IPアドレスによる経路選択は「ネットワーク層」の役割であり、「トランスポート層」と混同しないこと。

2IPアドレスとサブネットマスクの計算

CIDR表記(例: /24)は、32ビットのIPアドレスのうち先頭何ビットがネットワーク部かを表す。これを10進数のサブネットマスクに変換するには、ネットワーク部のビットを1、ホスト部のビットを0として8ビットずつ4つに区切り、それぞれを10進数に直せばよい。

CIDR表記2進数(最終オクテット)10進数のサブネットマスク
/2400000000255.255.255.0
/2510000000255.255.255.128
/2611000000255.255.255.192
/2711100000255.255.255.224
/2811110000255.255.255.240
公式: 割り当て可能ホスト数 割り当て可能なホスト数 = 232-n - 2 (nはCIDRのプレフィックス長)。ホスト部が全て0の「ネットワークアドレス」と全て1の「ブロードキャストアドレス」を除くため、2を引く。
例題1: 192.168.1.0/24 を4部署に均等分割する 4つの均等なサブネットに分けるには、2k≧4 を満たす最小の k=2 ビットをホスト部から借りる。よってプレフィックス長は 24+2=/26となり、1ブロックのサイズは 256÷4=64 個。
結果は次のとおり(各サブネットのホスト数は 2⁶-2=62)。
・192.168.1.0/26(ネットワークアドレス0、有効範囲1〜62、ブロードキャスト63)
・192.168.1.64/26(ネットワークアドレス64、有効範囲65〜126、ブロードキャスト127)
・192.168.1.128/26(ネットワークアドレス128、有効範囲129〜190、ブロードキャスト191)
・192.168.1.192/26(ネットワークアドレス192、有効範囲193〜254、ブロードキャスト255)
例題2: 2台のホストは同一サブネットか サブネットマスクが/26(255.255.255.192)のとき、172.16.5.130 と 172.16.5.190 は同一サブネットに属するか。
ブロックサイズは 2⁶=64。172.16.5.128〜172.16.5.191の範囲(128=64×2)にどちらも含まれるため、両者は同一サブネット(ネットワークアドレス172.16.5.128、ブロードキャスト172.16.5.191)に属する。130と190はいずれも有効ホスト範囲(129〜190)内であり、正しいホストアドレスである。
つまずきやすいポイント サブネット分割の計算では、ホスト部から借りるビット数を「必要なサブネット数」を基準に決めるのか「必要なホスト数」を基準に決めるのかを取り違えやすい。設問が「いくつのネットワークに分けるか」を問うているのか「1ネットワークに何台収容したいか」を問うているのかを最初に見極めること。また、ネットワークアドレスとブロードキャストアドレスは実機に割り当てられないため、ホスト数を求める際は必ず2を引く。

3TCPのコネクション確立とアドレス解決・名前解決

TCPはコネクション型のプロトコルであり、実際のデータ送信を始める前に、送信元と宛先の間でコネクション(仮想的な通信路)を確立する。この確立手順を「3ウェイハンドシェイク」と呼び、3つの制御パケットのやり取りによって、双方が「送受信の準備ができている」ことを確認し合う。

同一LAN内の通信では、IPアドレスが分かっていても実際にフレームを届けるにはMACアドレスが必要になる。この変換を行うのが「ARP(Address Resolution Protocol)」である。

手順内容
① ARP要求(ARP Request)送信元が「このIPアドレスを持つ機器のMACアドレスを教えてほしい」とLAN内へブロードキャストで問い合わせる
② ARP応答(ARP Reply)該当するIPアドレスを持つ機器が、自身のMACアドレスを問い合わせ元へユニキャストで返信する
③ ARPテーブルへ登録取得したIPアドレスとMACアドレスの対応をARPテーブル(キャッシュ)に一定時間保存し、以降の通信に再利用する

DNS(Domain Name System)は、ドメイン名とIPアドレスを相互に変換する分散型の仕組みである。クライアントはまずキャッシュDNSサーバ(フルサービスリゾルバ)に問い合わせ、そこがルートサーバ→TLD(トップレベルドメイン)サーバ→権威DNSサーバの順に反復的に問い合わせて(反復問い合わせ)、最終的な結果をクライアントへ返す(再帰問い合わせ)。DNSは用途に応じて複数のレコード種別を管理している。

レコード種別内容
Aレコードドメイン名に対応するIPv4アドレスを保持
AAAAレコードドメイン名に対応するIPv6アドレスを保持
MXレコードそのドメイン宛のメールを受け取るメールサーバを指定
NSレコードそのドメインを管理する権威DNSサーバ(ネームサーバ)を指定
CNAMEレコード別名(エイリアス)から正式なドメイン名への参照を指定
PTRレコードIPアドレスからドメイン名を求める逆引きに使用
つまずきやすいポイント ARPが解決できるのは同一セグメント内の機器のMACアドレスに限られる。宛先が別セグメントにある場合、IPヘッダの宛先IPアドレスは最終的な宛先ホストのままだが、フレームの宛先MACアドレスは「デフォルトゲートウェイ(ルータ)」のものになる点を混同しやすい。また3ウェイハンドシェイクは「SYN→SYN/ACK→ACK」の順序を正確に覚えること。

4NAT/NAPTとTLS(SSL)による通信の保護

IPv4アドレスの枯渇対策や社内ネットワークの保護のため、プライベートIPアドレスとグローバルIPアドレスを相互に変換する技術を「NAT(Network Address Translation)」と呼ぶ。単純なNATはプライベートIPアドレス1個をグローバルIPアドレス1個に対応させる方式(1対1)だが、実務でよく使われるのは、ポート番号まで変換することで複数の内部端末が少数(多くは1個)のグローバルIPアドレスを共有できる「NAPT(IPマスカレード)」である。

内部(プライベートIP:ポート)外部(グローバルIP:ポート)
192.168.1.10 : 50001203.0.113.5 : 60001
192.168.1.11 : 50002203.0.113.5 : 60002
192.168.1.12 : 50001203.0.113.5 : 60003
例題: NAPTによるアドレス変換の考え方 内部の3台の端末(192.168.1.10〜.12)が同時にインターネットへ接続しても、NAPTルータは通信ごとに異なるポート番号を割り当てて変換するため、外部から見るとグローバルIPアドレスは203.0.113.5の1個だけである。戻りの応答パケットは、宛先ポート番号(60001〜60003)をもとに、どの内部端末宛かをルータが判別して転送する。このようにポート番号は16ビットで表され最大65536通りあるため、1個のグローバルIPアドレスでも理論上は多数の内部端末の通信を同時に中継できる。

Webサイトとの通信では、盗聴・改ざん・なりすましを防ぐために、HTTPにTLS(Transport Layer Security、旧称SSL)を組み合わせたHTTPSが広く使われる。TLSは公開鍵暗号方式と共通鍵暗号方式を組み合わせて通信を保護する。

手順内容
① ClientHelloクライアントが対応する暗号方式(暗号スイート)の候補やランダム値をサーバへ送信する
② ServerHello + サーバ証明書サーバが使用する暗号方式を決定し、公開鍵を含むデジタル証明書を送付する(なりすまし防止)
③ 鍵交換公開鍵暗号方式を用いて、以降の通信で使う共通鍵(セッション鍵)を安全に共有する
④ 暗号化通信の開始共有した共通鍵による高速な共通鍵暗号方式で、実際のデータを暗号化して送受信する
つまずきやすいポイント 「NAT」と「NAPT(IPマスカレード)」を同じものとして扱ってしまいがちだが、単純なNATはIPアドレスのみを1対1で変換するのに対し、NAPTはポート番号まで変換することで複数端末が1つのグローバルIPアドレスを共有できる点が異なる。また、TLSは「公開鍵暗号方式だけ」でデータ本体を暗号化しているわけではなく、鍵交換に公開鍵暗号方式、実際のデータ通信には処理が高速な共通鍵暗号方式を使うという役割分担を理解しておく。
