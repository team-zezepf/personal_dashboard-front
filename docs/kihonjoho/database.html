データベースのまとめ

テーブル設計・SQL操作・トランザクション管理・障害回復・データ分析の活用など、データベースで問われる要点を図解しています。読み終えたら下部から問題を解いて定着させましょう。

1リレーショナルデータベースの基本構造とキー

リレーショナルデータベース(RDB)は、データを行(レコード)と列(フィールド・属性)からなる表(テーブル)の形式で管理する。1つの表の中で各行を一意に識別するために設定する列を主キーと呼び、値の重複やNULL(空)は許されない。

用語説明
主キー(プライマリキー)表内の各行を一意に識別する列。値の重複・NULLは不可
候補キー主キーの候補になりうる列(一意性を満たす列)。複数存在してよい
複合キー複数の列を組み合わせて初めて一意性を満たすキー
外部キー自分の表の列が、別の表の主キーを参照する形で設定するキー。表同士の関連付けと参照整合性の維持に使う

なお、表形式に縛られずキーバリュー型・ドキュメント型など多様なデータモデルを扱うデータベースの総称をNoSQLデータベースと呼び、RDBとは異なる設計思想を持つ。

練習問題 0 / 2問 正解

問1　自分の表の列が別の表の主キーを参照する形で設定し、表どうしの関連付けと参照整合性の維持に使うキーはどれか。

外部キーは、参照先の表に存在しない値が入らないようにする(参照整合性)ために使う。主キーは表内の各行を一意に識別する列、候補キーは主キーになりうる列、複合キーは複数の列を組み合わせて一意性を満たすキー。

問2　主キーの説明として、適切なものはどれか。

主キーは各行を一意に識別するため、値の重複もNULLも許されない。主キーは1つの表に1つだけ(候補キーは複数あってよい)。複数の列を組み合わせた複合キーを主キーにすることもできる。

2E-R図とカーディナリティ(多重度)

E-R図(実体関連図)は、データベースで扱う実体(エンティティ)同士の関係を図示したものである。実体間の対応関係の個数をカーディナリティ(多重度)といい、「1対1」「1対多」「多対多」の3種類で表す。

カーディナリティ具体例
1対11人の社員に対し社員証が1枚だけ対応する
1対多1人の顧客が複数の注文を行うが、1件の注文の顧客は1人
多対多1人の生徒が複数の授業を受け、1つの授業に複数の生徒が参加する
つまずきやすいポイント どちら側が「多」なのかは、矢印(線)の両端に立って文章にして確認するとよい。「1人の顧客は複数の注文を行うことができるが、1件の注文は1人の顧客に対応する」ので顧客側が1、注文側が多となる。
練習問題 0 / 2問 正解

問1　1冊の本は1つの出版社から出版され、1つの出版社は複数の本を出版する。「出版社」と「本」のカーディナリティはどれか。

「1つの出版社は複数の本を出版する」ので出版社側が1、本側が多になり、出版社:本 = 1対多。「1冊の本の出版社は1つ」なので多対多ではない。イは出版社と本を逆に見た場合。

問2　多対多の関係にある2つの実体を、リレーショナルデータベースで表現する方法として、適切なものはどれか。

例えば「生徒」と「授業」の多対多は、「受講」のような中間の表を設けて、生徒:受講 = 1対多、授業:受講 = 1対多に分解する。イのように繰り返し項目を持たせると、1つのセルに複数の値が入る非正規形になってしまう。

3正規化

正規化とは、データの重複を排除し、挿入・更新・削除時に矛盾(更新異常)が生じないようにテーブル構造を整理する設計手法である。逆に、検索速度などを優先してあえてデータを重複させる設計は非正規化(デノーマライゼーション)と呼ばれ、正規化とは目的が異なる。

受注番号顧客名商品(繰り返し項目)
1001山田太郎ノートPC, マウス
1002佐藤花子キーボード
例題: 非正規形 → 第1正規形 上の表は1つのセル(商品欄)に複数の値が入っている「非正規形」である。1つのセルには1つの値だけが入るよう行を分割すると、次のようになる。
(1001, 山田太郎, ノートPC) / (1001, 山田太郎, マウス) / (1002, 佐藤花子, キーボード)
これが第1正規形である。

正規化はさらに段階を踏んで進む。第2正規形は複合キーの一部だけに従属する項目(部分関数従属)を分離した状態、第3正規形はキー以外の項目同士が従属関係(推移的関数従属)を持つ場合にそれも分離した状態である。

つまずきやすいポイント 正規化は「データの重複を排除して更新時の矛盾を防ぐ」ための設計であり、「検索速度を高めるためにあえてデータを重複させる」非正規化とは逆方向の考え方である。両者を混同しないこと。
練習問題 0 / 2問 正解

問1　正規化の目的として、適切なものはどれか。

正規化は、データの重複を排除して更新異常を防ぐための設計手法。アとエは、検索速度を優先してあえて重複させる「非正規化」の考え方。

問2　第3正規形の説明として、適切なものはどれか。

第3正規形は、第2正規形からさらに「キー以外の項目が、別のキー以外の項目に従属する」関係を別の表に分離した状態。アは第1正規形、イは第2正規形の説明。ウは非正規化。

4SQLの基本操作(SELECT・WHERE・JOIN)

SQLの基本命令には、検索のSELECT、追加のINSERT、更新のUPDATE、削除のDELETEがある。SELECT文でどの表(FROM句)からどの条件(WHERE句)でデータを取り出すかを指定する。

例題: 条件を指定して抽出する テーブル「社員」から部署が「営業部」の氏名だけを取り出したい場合、次のように書く。
SELECT 氏名 FROM 社員 WHERE 部署 = '営業部';
WHERE句が抽出条件(絞り込み条件)を指定する部分である。
結合(JOIN)の種類取得される行
INNER JOIN(内部結合)両方のテーブルでキーが一致する行だけ
LEFT OUTER JOIN(左外部結合)左側の全行+一致するBの値(なければNULL)
RIGHT OUTER JOIN(右外部結合)右側の全行+一致するAの値(なければNULL)
FULL OUTER JOIN(完全外部結合)両方の全行(一致しない側はNULLで補う)
つまずきやすいポイント INNER JOINは「一致する行だけ」を残すため、キーが対応しない行は結果から消える。片方のテーブルの行を漏らさず残したい場合はOUTER JOIN(LEFT/RIGHT/FULL)を使う必要があり、単に「JOIN」とだけ書くとINNER JOINになる点に注意。
練習問題 0 / 2問 正解

問1　表「商品」から、単価が1000以上の行の商品名を取り出すSQL文として、適切なものはどれか。

SELECT の後に取り出す列、FROM の後に表、WHERE の後に抽出条件を書く。アは表名と列名が逆、ウは句の順序が誤り(FROM は WHERE より前)、エは条件と取り出す列が入れ替わっている。

問2　表A(左)と表B(右)を結合するとき、表Aの全行を残し、表Bに一致する行がない部分はNULLで補う結合はどれか。

左側(表A)の全行を残すのは LEFT OUTER JOIN。INNER JOIN は両方でキーが一致する行だけを残す。RIGHT OUTER JOIN は右側(表B)の全行を残し、FULL OUTER JOIN は両方の全行を残す。

5インデックスとビュー

インデックス(索引)は、本の索引のように、特定の列の値をあらかじめ整理しておくことで検索速度を向上させる仕組みである。多くのRDBMSではB-tree(B木)と呼ばれる木構造が使われ、全件を走査せずに少ない比較回数で目的の行にたどり着ける。

項目インデックスビュー
目的検索速度の向上複雑な問い合わせの再利用・簡略化
実データの保持保持しない(元データを指し示す構造)保持しない(SELECT結果を都度表示する仮想表)
更新への影響列の更新のたびに索引も再構築され、更新コストが増える元テーブルの更新内容がそのままビューにも反映される
つまずきやすいポイント インデックスは検索(SELECT)を速くする一方、更新(INSERT/UPDATE/DELETE)のたびに索引の再構築が必要になるためオーバーヘッドが増える。「多いほど良い」わけではない点に注意。
練習問題 0 / 2問 正解

問1　インデックス(索引)の説明として、適切なものはどれか。

インデックスは検索(SELECT)を速くする一方、INSERT・UPDATE・DELETE のたびに索引の再構築が必要になる。そのため多ければ良いわけではない。エはビューの説明。

問2　ビューの説明として、適切なものはどれか。

ビューはSELECT文の結果を表のように扱える仮想表で、複雑な問い合わせの再利用や簡略化に使う。実データを持たないので、元の表の更新はそのままビューにも反映される(ウは誤り)。アはインデックスの説明。

6トランザクション管理(ACID特性)と排他制御

一連の更新処理をひとまとまりとして扱う単位をトランザクションという。トランザクションが備えるべき4つの性質の頭文字を取ってACID特性と呼ぶ。

性質英語内容
原子性Atomicity処理の途中経過が残らず、すべて実行されるか全く実行されないかのいずれかになる
一貫性Consistencyトランザクションの前後でデータベースの整合性(制約)が保たれる
独立性(分離性)Isolation複数のトランザクションを同時に実行しても、互いに影響を与えない
持続性Durabilityコミットした結果は、障害が起きてもデータベースに残り続ける
例題: 排他制御とは 複数の利用者が同じ口座残高を同時に更新すると、後の更新が先の更新を上書きしてしまい整合性が崩れるおそれがある。そこで更新中の行にロックをかけ、他の処理からの同時更新を待たせる仕組みが排他制御である。
つまずきやすいポイント 排他制御(ロックの仕組みそのもの)と、デッドロック(複数の処理が互いに相手のロック解除を待ち続け、どちらも先に進めなくなる状態)は別の概念。また、コミット(更新確定)とロールバック(更新取り消し)も対になる操作として混同しないこと。
練習問題 0 / 2問 正解

問1　ACID特性のうち、コミットしたトランザクションの結果は、その後に障害が起きても失われないという性質はどれか。

持続性(Durability)は、コミットした結果がデータベースに残り続ける性質。原子性はすべて実行されるか全く実行されないかのどちらかになる性質、一貫性は前後で整合性が保たれる性質、独立性は同時に実行しても互いに影響しない性質。

問2　デッドロックの説明として、適切なものはどれか。

デッドロックは、例えばトランザクション1がデータAをロックしてBを待ち、トランザクション2がBをロックしてAを待つような状態。アは排他制御(ロック)の仕組みそのもの、イはロールバック、エは排他制御をしないときに起きる問題。

7障害回復(ログ・チェックポイント・ロールフォワード)と2相コミット

DBMSは、障害が起きてもデータベースを正しい状態に戻せるよう、更新のたびに更新前の値(更新前ログ)と更新後の値(更新後ログ)をログファイルに記録している。また、一定間隔でメモリ上の更新内容をディスクに書き出し、その時点をチェックポイントとして記録する。

回復処理使うもの内容主な障害
ロールバック(後退復帰)更新前ログ処理中のトランザクションの更新を取り消し、開始前の状態に戻すトランザクション障害、システム障害時の未コミット分
ロールフォワード(前進復帰)バックアップ + 更新後ログバックアップ(またはチェックポイント)の状態から、コミット済みの更新をやり直して反映する媒体障害(ディスクの故障)、システム障害時のコミット済み分
例題: システム障害が起きたときの回復 チェックポイントの後、障害発生までにコミット済みのトランザクションは、更新がディスクに反映されていない可能性があるのでロールフォワードする。障害発生時点で未コミットのトランザクションは、途中までの更新をロールバックで取り消す。チェックポイントより前にコミット済みのものは、ディスクに書き出されているので何もしなくてよい。

複数のサーバにまたがる分散データベースで、すべてのサーバの更新をそろって確定させるための手順を2相コミットという。調停役が各サーバに「コミットできるか」を問い合わせ(第1相)、全員から「できる」と返事があればコミットを、1台でも「できない」ならロールバックを指示する(第2相)。

つまずきやすいポイント ロールバックは「更新前ログで戻す(取り消す)」、ロールフォワードは「更新後ログで進める(やり直す)」。ディスクが壊れた媒体障害では、まずバックアップを復元し、その後に更新後ログでロールフォワードする。
練習問題 0 / 2問 正解

問1　データベースを格納したディスクが故障した(媒体障害)ときの回復方法として、適切なものはどれか。

媒体障害では、まずバックアップを戻し、その後のコミット済みの更新を更新後ログでやり直す(ロールフォワード)。アのロールバックは、処理中のトランザクションの更新を取り消すときに使う。2相コミットは分散データベースで更新を確定させる手順で、障害回復の方法ではない。

問2　システム障害が起きたとき、障害の時点でコミットされていなかったトランザクションに対して行う処理はどれか。

未コミットのトランザクションは途中までの更新が残っているおそれがあるので、更新前ログで取り消して開始前の状態に戻す(原子性を保つ)。ロールフォワードは、コミット済みなのにディスクに反映されていない可能性のある更新に対して行う。

8データの分析と活用(ビッグデータ・データマイニング)

業務で蓄積された大量のデータを分析して、経営や業務に役立てる技術も問われる。

用語説明
ビッグデータ量(Volume)・種類(Variety)・発生頻度(Velocity)が大きく、従来のDBMSでは扱いにくい大量のデータ
データウェアハウス業務システムのデータを時系列で蓄積し、分析しやすい形に統合したデータベース
データマートデータウェアハウスから、部門や目的ごとに必要なデータだけを取り出したもの
データレイク構造化・非構造化を問わず、データを加工せずそのままの形式で蓄積しておく保管場所
データマイニング大量のデータを統計的な手法などで分析し、隠れた規則性や関係(「おむつとビールが一緒に買われる」など)を見つけ出すこと
ETL業務システムからデータを抽出(Extract)・変換(Transform)し、データウェアハウスに書き出す(Load)処理
OLAPデータを地域別・商品別・期間別など多次元で集計・分析すること(切り口を変える=ダイス、詳細化する=ドリルダウン)
つまずきやすいポイント データウェアハウスは「分析用に整理して蓄積」、データレイクは「加工せずそのまま蓄積」、データマイニングは「蓄積したデータから規則性を発見する分析」。保管場所の名前と分析手法の名前を混同しない。
練習問題 0 / 2問 正解

問1　構造化・非構造化を問わず、データを加工せずにそのままの形式で蓄積しておく保管場所はどれか。

データレイクは「加工せずそのまま蓄積」する。データウェアハウスは分析しやすい形に統合して時系列で蓄積したもの、データマートはそこから部門や目的ごとに必要なデータを取り出したもの。データマイニングは蓄積したデータから規則性を見つける分析のこと。

問2　業務システムからデータを抽出し、変換して、データウェアハウスに書き出す処理はどれか。

ETLは Extract(抽出)・Transform(変換)・Load(書き出し)の頭文字。OLAPはデータを地域別・期間別などの多次元で集計・分析すること、データマイニングは隠れた規則性を見つけ出すこと。
