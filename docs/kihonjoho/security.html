セキュリティのまとめ

暗号方式・認証技術・代表的なサイバー攻撃とその対策、情報セキュリティ管理・PKI・ネットワークの防御など、セキュリティで問われる要点を図解しています。読み終えたら下部から問題を解いて定着させましょう。

1暗号方式(共通鍵暗号方式・公開鍵暗号方式・ハイブリッド暗号)

通信内容を第三者に読まれないようにするため、平文を暗号文に変換することを暗号化、暗号文を平文に戻すことを復号という。暗号化・復号に使う鍵の扱い方によって、共通鍵暗号方式と公開鍵暗号方式の2種類に大別される。

方式鍵の関係鍵の配送処理速度
共通鍵暗号方式暗号化・復号に同一の鍵を使う鍵を安全に事前共有する必要がある(鍵配送問題)比較的高速
公開鍵暗号方式暗号化(公開鍵)と復号(秘密鍵)で異なる鍵を使う公開鍵は第三者に公開してよい共通鍵暗号方式より低速

実際の通信(TLS/SSLなど)では、両方式の長所を組み合わせた「ハイブリッド暗号方式」が使われる。データ本体は高速な共通鍵暗号方式で暗号化し、その共通鍵(セッション鍵)だけを公開鍵暗号方式で安全に受け渡す。

例題: ハイブリッド暗号方式の流れ ① 送信者はランダムな共通鍵(セッション鍵)を生成する。② データ本体をその共通鍵で暗号化する。③ 共通鍵自体を受信者の公開鍵で暗号化して送る。④ 受信者は自分の秘密鍵で共通鍵を復号し、その共通鍵でデータ本体を復号する。公開鍵暗号方式は鍵の受け渡しだけに使い、データ本体は高速な共通鍵暗号方式で処理するのがポイントである。
つまずきやすいポイント 公開鍵暗号方式では、送信者が受信者の公開鍵で暗号化し、受信者が自分の秘密鍵で復号する(秘密鍵は復号する側だけが持つ)。「どちらの鍵で暗号化するか」を逆に覚えやすいので注意する。
練習問題 0 / 2問 正解

問1　公開鍵暗号方式を使って、AさんがBさんに暗号化したデータを送る。Aさんが暗号化に使う鍵はどれか。

送信者は受信者(Bさん)の公開鍵で暗号化し、受信者は自分の秘密鍵で復号する。秘密鍵は復号する側(Bさん)だけが持っているので、Bさん以外は復号できない。

問2　ハイブリッド暗号方式で、送信するデータ本体を暗号化する方法として、適切なものはどれか。

データ本体は処理の速い共通鍵暗号方式で暗号化し、その共通鍵だけを受信者の公開鍵で暗号化して送る。こうして、共通鍵暗号の速さと公開鍵暗号の鍵配送のしやすさを両立する。ハッシュ関数は元に戻せないので、暗号化には使えない。

2デジタル署名とハッシュ関数

ハッシュ関数は、入力データから固定長のハッシュ値(メッセージダイジェスト)を生成する関数である。同じ入力からは常に同じハッシュ値が得られる一方、ハッシュ値から元のデータを逆算することは極めて困難(一方向性)であり、パスワードの保管やデータの改ざん検知に利用される。

用途説明
パスワードの保管パスワードそのものではなくハッシュ値を保存し、漏えい時の被害を軽減する
改ざん検知送信前後のハッシュ値を比較し、データが変更されていないか確認する
デジタル署名文書のハッシュ値を送信者の秘密鍵で暗号化(署名)し、本人性・完全性を証明する

デジタル署名は、公開鍵暗号方式の鍵の使い方を「逆向き」に利用する技術である。送信者は文書のハッシュ値を自分の秘密鍵で暗号化(署名)し、文書とともに送る。受信者は送信者の公開鍵でその署名を復号し、自分で計算したハッシュ値と一致するか確認することで、本人性(なりすましでないこと)と完全性(改ざんされていないこと)を確認できる。

例題: 署名が一致しない場合 受信した文書が通信途中で改ざんされていた場合、受信者が計算するハッシュ値Aは元の文書のものと変わってしまう。一方、署名から得られるハッシュ値Bは送信時のまま変化しない。そのためAとBが一致せず、改ざんを検知できる。
つまずきやすいポイント ハッシュ関数は鍵を使わない一方向の変換であり、鍵を使って行う暗号化(復号可能)とは異なる。また、通常の公開鍵暗号(秘匿目的)が「公開鍵で暗号化→秘密鍵で復号」なのに対し、デジタル署名は逆に「秘密鍵で署名→公開鍵で検証」する点を混同しないよう注意する。
練習問題 0 / 2問 正解

問1　デジタル署名で、受信者が署名を検証するときに使う鍵はどれか。

送信者は文書のハッシュ値を自分の秘密鍵で暗号化して署名し、受信者は送信者の公開鍵で署名を復号して、文書から計算したハッシュ値と比べる。秘匿目的の公開鍵暗号とは、鍵の使い方が逆になる。

問2　ハッシュ関数の性質として、適切なものはどれか。

ハッシュ関数は鍵を使わない一方向の変換で、入力の長さに関係なく固定長のハッシュ値を生成する。同じ入力からは常に同じ値になるので、改ざん検知やパスワードの保管に使える。

3利用者認証の技術

利用者認証に用いる情報は、大きく「知識情報(本人だけが知っている情報)」「所持情報(本人だけが持っている物)」「生体情報(本人の身体的特徴)」の3種類に分類される。このうち異なる種類の要素を2つ以上組み合わせて本人確認を行う方式を多要素認証(MFA)と呼ぶ。

知識情報: パスワード・暗証番号など、本人の記憶
所持情報: ICカード・スマートフォンなど、本人の所持物
生体情報: 指紋・顔・虹彩など、身体的特徴
ワンタイムパスワード: ログインのたびに変わる使い捨てパスワード
用語説明
多要素認証(MFA)知識・所持・生体など異なる種類の要素を組み合わせて認証する方式
ワンタイムパスワードログインのたびに変化する一回限り有効なパスワード。盗聴・使い回しによる不正ログインのリスクを低減する
シングルサインオン(SSO)一度の認証で複数のシステム・サービスを利用できるようにする仕組み(利便性の向上が目的)
ゼロトラスト社内・社外を区別せず、あらゆる通信を信頼せず都度検証するという考え方
つまずきやすいポイント 多要素認証は「異なる種類」の要素を組み合わせる方式であり、同じ種類の情報を2回聞く(例: パスワードを2回入力させる)ことは多要素認証にはあたらない。また、シングルサインオンは認証の「利便性」を高める仕組みであり、認証を「強化」するワンタイムパスワードや多要素認証とは目的が異なる点に注意する。
練習問題 0 / 2問 正解

問1　多要素認証に該当するものはどれか。

多要素認証は、知識情報・所持情報・生体情報のうち異なる種類を組み合わせる。エはパスワード(知識)とICカード(所持)の組合せ。アとイはどちらも知識情報、ウはどちらも生体情報なので、多要素認証にはならない。

問2　一度の認証で、複数のシステムやサービスを利用できるようにする仕組みはどれか。

シングルサインオン(SSO)は利便性の向上を目的とした仕組み。ゼロトラストは社内外を区別せず通信を都度検証する考え方、ワンタイムパスワードはログインのたびに変わる使い捨てのパスワード、多要素認証は異なる種類の要素を組み合わせる認証方式。

4人や仕組みの隙を突く攻撃

情報セキュリティに対する攻撃には、技術的な脆弱性を突くものだけでなく、人の心理的な隙や行動のミスにつけ込むものもある。代表的な手口とその特徴を整理する。

攻撃手法概要
フィッシング実在する組織・人物になりすましたメールや偽のWebサイトで、ID・パスワードやクレジットカード情報をだまし取る
ソーシャルエンジニアリング技術的手段ではなく、なりすまし・盗み見・電話での聞き出しなど、人の心理的な隙や行動のミスにつけ込んで情報を盗む手法の総称
ブルートフォース攻撃(総当たり攻撃)考えられる文字の組み合わせを片っ端から試してパスワードを解析する
ゼロデイ攻撃ソフトウェアの脆弱性が発見されてから修正プログラム(パッチ)が提供されるまでの無防備な期間を狙う
例題: フィッシングとソーシャルエンジニアリングの違い 銀行を装った偽のメールからニセのログイン画面に誘導し、入力されたIDとパスワードを盗み取るのはフィッシング(なりすましメール・偽サイトという仕掛けを伴う)。一方、清掃員などになりすまして社内に侵入し、机の上のメモに書かれたパスワードを盗み見るのはソーシャルエンジニアリング(技術を使わず人の隙を突く)である。
つまずきやすいポイント フィッシングは「偽のWebサイトへ誘導する」という技術的な仕掛けを伴うのに対し、ソーシャルエンジニアリングは技術を使わず人間の心理・行動の隙を突く点で異なる。また、ブルートフォース攻撃(総当たり)と辞書攻撃(よく使われる単語のリストを試す)も混同しやすいので区別しておく。
練習問題 0 / 2問 正解

問1　上司を名乗って電話をかけ、担当者からパスワードを聞き出す攻撃はどれか。

ソーシャルエンジニアリングは、技術を使わずに人の心理的な隙や行動のミスにつけ込む攻撃。フィッシングは偽のメールやWebサイトに誘導して情報をだまし取る攻撃、ブルートフォース攻撃は文字の組合せを総当たりで試す攻撃。

問2　ソフトウェアの脆弱性が発見されてから、修正プログラムが提供されるまでの期間を狙う攻撃はどれか。

ゼロデイ攻撃は、修正プログラム(パッチ)が提供される前の無防備な期間を狙う。DoS攻撃は大量の要求を送りつけてサービスを利用できなくする攻撃。

5Webアプリケーションへの攻撃

Webアプリケーションの入力欄に対するチェックが不十分だと、攻撃者が想定外のデータを送り込むことでシステムを不正に操作できてしまう。代表的な攻撃としてSQLインジェクションとクロスサイトスクリプティング(XSS)がある。

例題: SQLインジェクションによるログイン突破 ログインフォームのパスワード欄に「' OR '1'='1」のような文字列を入力すると、Webアプリが組み立てるSQL文の条件式が常に真になってしまい、本来のパスワードを知らなくてもログインが成立してしまうことがある。対策としては、入力値をそのままSQL文に埋め込まず、プレースホルダ(バインド機構)を使うなどの方法が有効である。
攻撃実行される場所主な被害主な対策
SQLインジェクションWebサーバ側のデータベース不正なデータ閲覧・改ざん・削除、認証の突破入力値検証、プレースホルダ(バインド機構)の利用
クロスサイトスクリプティング(XSS)閲覧者(利用者)のブラウザ側Cookie等の情報窃取、なりすまし入力値のサニタイジング(エスケープ処理)
つまずきやすいポイント SQLインジェクションは「サーバ側」のデータベースで不正なSQLが実行されるのに対し、XSSは「閲覧者側」のブラウザで不正なスクリプトが実行される点で攻撃の対象が異なる。どちらも入力値のチェック(検証・無害化)が不十分なことが原因である点は共通している。
練習問題 0 / 2問 正解

問1　SQLインジェクションへの対策として、適切なものはどれか。

プレースホルダを使うと、入力値はSQL文の一部ではなく単なる値として扱われるので、入力された文字列がSQLとして実行されなくなる。アはクロスサイトスクリプティング(XSS)の対策。通信の暗号化は盗聴の対策で、SQLインジェクションは防げない。

問2　クロスサイトスクリプティング(XSS)で、攻撃者が埋め込んだスクリプトが実行される場所はどれか。

XSSでは、脆弱なサイトに埋め込まれたスクリプトが閲覧者のブラウザで実行され、Cookieなどの情報が盗まれる。サーバ側のデータベースで不正なSQLが実行されるのはSQLインジェクション。

6マルウェア・DoS攻撃と防御技術

利用者に害を及ぼす意図で作られたソフトウェアを総称してマルウェアと呼ぶ。マルウェアそのものではないが、外部からの不正アクセスやサービス妨害を防ぐための仕組みも合わせて理解しておく。

ランサムウェア: データを暗号化するなどして使用不能にし、復旧と引き換えに金銭を要求する
ワーム: 単独で自己増殖し、ネットワークを通じて他のコンピュータへ感染を広げる
トロイの木馬: 無害なソフトウェアを装って侵入し、内部で不正な動作を行う
防御の仕組み役割
ファイアウォール内部ネットワークと外部ネットワークの境界に設置し、あらかじめ定めた規則に基づいて通信を許可・拒否する
ウイルス対策ソフト既知のマルウェアの特徴をまとめたウイルス定義ファイル(パターンファイル)と照合してマルウェアを検知・駆除する
VPNインターネットなどの公衆回線上に、暗号化した仮想的な専用線を構築して安全に通信する
プロキシサーバ内部の端末に代わって外部と通信を中継し、アクセス制御やキャッシュなどを行う
つまずきやすいポイント ファイアウォールは「通信の可否」をルールに基づいて判断する仕組みであり、マルウェア自体を検知するものではない。マルウェアの検知・駆除にはウイルス対策ソフト(ウイルス定義ファイルとの照合)が必要であり、両者は役割が異なる。また、ファイアウォール自体はランサムウェアやワームのような「マルウェア」には分類されない点にも注意する。
練習問題 0 / 2問 正解

問1　データを暗号化するなどして使用できなくし、復旧と引き換えに金銭を要求するマルウェアはどれか。

ランサムウェアは「身代金(ランサム)」を要求するマルウェア。ワームは単独で自己増殖して感染を広げ、トロイの木馬は無害なソフトウェアを装って侵入する。スパイウェアは利用者の情報をひそかに収集して外部に送る。

問2　単独で自己増殖し、ネットワークを通じて他のコンピュータへ感染を広げるマルウェアはどれか。

ワームは他のプログラムに寄生せず、単独でネットワーク経由で広がる。トロイの木馬は自己増殖せず、無害なソフトウェアを装って侵入する。ファイアウォールはマルウェアではなく、通信の可否を判断する防御の仕組み。

7情報セキュリティ管理(CIA・リスクマネジメント・ISMS・CSIRT)

情報セキュリティとは、情報の機密性・完全性・可用性の3つ(頭文字をとってCIA)を維持することである。技術的な対策だけでなく、組織としてリスクを管理する仕組みも問われる。

要素意味損なわれる例
機密性(Confidentiality)許可された人だけが情報にアクセスできる情報漏えい、盗み見
完全性(Integrity)情報が正確で、改ざんされていないWebページの改ざん、データの破損
可用性(Availability)必要なときに情報やシステムを使えるDoS攻撃によるサービス停止、ランサムウェア

組織のリスクへの取り組みは、リスクを洗い出し(特定)、大きさを見積もり(分析)、対応の優先度を決める(評価)というリスクアセスメントから始め、そのあとリスク対応を選ぶ。

リスク対応内容例
リスク回避リスクの原因となる活動そのものをやめる個人情報を扱う事業から撤退する
リスク低減対策をして、発生確率や影響を小さくするウイルス対策ソフトの導入、暗号化
リスク移転(共有)損失を他者と分け合うサイバー保険への加入、業務の外部委託
リスク保有(受容)対策をせず、損失を受け入れる影響が小さいリスクをそのままにする
用語説明
ISMS(情報セキュリティマネジメントシステム)組織が情報セキュリティをPDCAサイクルで継続的に管理・改善する仕組み。JIS Q 27001(ISO/IEC 27001)で要求事項が定められ、認証制度がある
情報セキュリティポリシー組織の情報セキュリティへの取り組みを示す文書。経営陣が定める「基本方針」、具体的な規則を定めた「対策基準」、手順を示す「実施手順」からなる
CSIRT(シーサート)セキュリティインシデントが起きたときに、報告を受け付けて調査・対応を行う組織内のチーム
SOC(ソック)ネットワークや機器を24時間監視し、攻撃の検知・分析を行う組織
つまずきやすいポイント 保険をかけるのは損失を他者に負担してもらう「移転」であり、「低減」ではない。また、情報セキュリティポリシーの基本方針は経営陣(トップ)が定めて組織全体に示すものであり、情報システム部門だけで決めるものではない。
練習問題 0 / 2問 正解

問1　DoS攻撃によってWebサイトが応答しなくなった。主に損なわれた情報セキュリティの要素はどれか。

可用性は、必要なときに情報やシステムを使えること。サービスが止まると可用性が損なわれる。機密性は許可された人だけがアクセスできること(漏えいで損なわれる)、完全性は情報が正確で改ざんされていないこと(改ざんで損なわれる)。

問2　サイバー保険に加入して、情報漏えいが起きたときの損失を補えるようにした。このリスク対応はどれか。

保険への加入は、損失を他者に負担してもらう「リスク移転(共有)」。リスク回避は原因となる活動自体をやめること、リスク低減は対策で発生確率や影響を小さくすること、リスク保有は対策をせず損失を受け入れること。

8ネットワークの防御(DMZ・IDS/IPS・WAF)

ファイアウォールだけでは防げない攻撃に備えて、複数の仕組みを組み合わせて守る。

仕組み役割
DMZ(非武装地帯)インターネットと内部ネットワークの間に設ける区域。外部に公開するWebサーバなどを置き、内部ネットワークと切り離す
IDS(侵入検知システム)通信を監視し、不正な侵入の兆候を検知して管理者に通知する
IPS(侵入防止システム)不正な通信を検知したうえで、その通信を遮断するところまで行う
WAF(Webアプリケーションファイアウォール)Webアプリケーションへの通信の中身を検査し、SQLインジェクションやXSSなどの攻撃を防ぐ
リバースプロキシ外部からのアクセスを受け付けてWebサーバに中継する。Webサーバを直接外部にさらさずに済む
つまずきやすいポイント IDSは「見つけて知らせる」まで、IPSは「見つけて止める」まで行う。一般的なファイアウォールはIPアドレスやポート番号で通信を許可・拒否するため、正規のポート(HTTPSの443番など)を通るWebアプリケーションへの攻撃は防げない。それを防ぐのがWAFである。

問1　通信を監視して不正な通信を検知し、その通信を遮断するところまで行う仕組みはどれか。

IPS(侵入防止システム)は「見つけて止める」まで行う。IDS(侵入検知システム)は「見つけて知らせる」まで。DMZはインターネットと内部ネットワークの間に設ける区域、リバースプロキシは外部からのアクセスを受けてWebサーバに中継する仕組み。

問2　外部に公開するWebサーバやメールサーバを置くために、インターネットと内部ネットワークの間に設ける区域はどれか。

DMZ(非武装地帯)に公開サーバを置けば、そのサーバが乗っ取られても、ファイアウォールが内部ネットワークへの通信を遮断できる。公開サーバを内部ネットワークに置くと、乗っ取られたときに内部まで被害が広がる。SOCは機器を監視して攻撃を検知・分析する組織。

9PKIとデジタル証明書

公開鍵暗号やデジタル署名では、「その公開鍵が本当に本人のものか」を確かめる必要がある。信頼できる第三者機関である認証局(CA)が、公開鍵とその持ち主を結び付けるデジタル証明書(電子証明書)を発行して保証する仕組みをPKI(公開鍵基盤)という。

用語説明
認証局(CA)本人確認をしたうえで、デジタル証明書を発行・失効させる機関
デジタル証明書持ち主の情報・公開鍵・有効期限などに、認証局がデジタル署名をしたもの(サーバ証明書、クライアント証明書など)
CRL(証明書失効リスト)有効期限前に失効させた証明書の一覧。秘密鍵が漏えいした場合などに失効させる
ルート証明書認証局自身の証明書。ブラウザやOSにあらかじめ組み込まれており、他の証明書の検証の起点になる
例: HTTPSでのサーバ証明書の検証 ブラウザはWebサーバから受け取ったサーバ証明書の署名を、認証局の公開鍵(ルート証明書)で検証する。検証に成功すれば、接続先が本物のサーバであり、証明書に含まれる公開鍵が本物であると確認できる。
つまずきやすいポイント デジタル証明書に含まれるのは公開鍵であり、秘密鍵は含まれない。デジタル証明書は「公開鍵の持ち主が誰か」を保証するもので、通信内容を暗号化するもの自体ではない。
練習問題 0 / 2問 正解

問1　デジタル証明書に含まれないものはどれか。

デジタル証明書は、持ち主の情報・公開鍵・有効期限などに認証局がデジタル署名をしたもので、「その公開鍵の持ち主が誰か」を保証する。秘密鍵は持ち主だけが管理するもので、証明書には含まれない。

問2　秘密鍵の漏えいなどにより、有効期限より前に失効させたデジタル証明書の一覧はどれか。

CRL(証明書失効リスト)で、証明書が失効していないかを確認できる。ルート証明書は認証局自身の証明書で検証の起点になるもの、サーバ証明書はWebサーバの正当性を証明する証明書、認証局は証明書を発行・失効させる機関。

10メールのセキュリティとセキュリティ対策の技術

送信元を偽ったなりすましメールへの対策や、マルウェアや脆弱性を調べるための技術も問われる。

技術説明
SPF送信元ドメインが、正規のメールサーバのIPアドレスをDNSに登録しておき、受信側が送信元サーバのIPアドレスと照合してなりすましを見抜く
DKIM送信側のメールサーバがメールにデジタル署名を付け、受信側がDNSに公開された公開鍵で検証する。送信元の正当性と改ざんの有無を確認できる
S/MIME電子メールの暗号化とデジタル署名を行う規格
サンドボックス隔離された仮想環境で不審なプログラムを実際に動かし、挙動を観察してマルウェアかどうかを判定する
ペネトレーションテスト攻撃者の立場で実際にシステムに侵入を試み、脆弱性がないかを検査する
ファジング予測できないデータ(ファズ)を大量に入力して、ソフトウェアの脆弱性を見つける
デジタルフォレンジックスインシデント発生後に、ログや記録媒体を証拠として保全・分析し、原因や被害を調べる
ハニーポットわざと侵入しやすくしたおとりのシステムを置き、攻撃の手口を観察・記録する
つまずきやすいポイント SPFは「送信元サーバのIPアドレス」で、DKIMは「デジタル署名」で送信元を確認する。サンドボックスは「実際に動かして調べる」、ファジングは「異常なデータを入力して調べる」点で区別する。
練習問題 0 / 2問 正解

問1　送信元ドメインの正規のメールサーバのIPアドレスをDNSに登録しておき、受信側が送信元サーバのIPアドレスと照合して、なりすましを見つける技術はどれか。

SPFは「送信元サーバのIPアドレス」で送信元を確認する。DKIMは送信側のメールサーバが付けたデジタル署名を、DNSに公開された公開鍵で検証する。S/MIMEはメールの暗号化とデジタル署名を行う規格。

問2　隔離された仮想環境で不審なプログラムを実際に動かし、その挙動を観察してマルウェアかどうかを判定する技術はどれか。

サンドボックスは「実際に動かして調べる」技術。ハニーポットはわざと侵入しやすくしたおとりのシステムで攻撃の手口を観察するもの、ファジングは予測できないデータを大量に入力して脆弱性を探すもの、ペネトレーションテストは攻撃者の立場で実際に侵入を試みる検査。
