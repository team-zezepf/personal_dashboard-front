ソフトウェアのまとめ

OSの役割・基本機能やタスクのスケジューリング、仮想記憶とページ置換、ミドルウェア・デバイスドライバなどの周辺ソフトウェア、ソフトウェアの品質特性・配布形態など、ソフトウェア分野で問われる要点を図解しています。読み終えたら下部から問題を解いて定着させましょう。

1ソフトウェアの品質特性

ソフトウェアの品質は、JIS X 0129(ISO/IEC 9126)により機能性・信頼性・使用性・効率性・保守性・移植性の6つの特性に整理されている。試験では各特性の説明文を読み、どの特性を指しているかを見分ける問題が出やすい。

特性説明
機能性利用者が必要とする機能を、指定された条件下で備えている度合い
信頼性指定された条件下で、要求された機能を維持して動作し続ける能力
使用性利用者が理解し、習得し、使用しやすい度合い
効率性少ない資源で効率よく処理を行う能力
保守性システムの機能を理解し、修正しやすい度合い
移植性別の環境(機種・OSなど)に移しやすい度合い
例題: 「信頼性」の説明として最も適切なものはどれか 選択肢: ①必要なときにシステムを利用できる度合い ②指定された条件下で、要求された機能を維持して動作し続ける能力 ③少ない資源で効率よく処理を行う能力 ④システムの機能を理解し、修正しやすい度合い
①は可用性、③は効率性、④は保守性の説明である。よって正解は②。
つまずきやすいポイント 「信頼性」と「可用性」は混同しやすい。信頼性は障害を起こさず動作し続ける能力(壊れにくさ)を指すのに対し、可用性は必要なときにシステムを利用できる度合い(稼働率のようなもの)を指す。試験では選択肢として並べて出されることが多いので、意味の違いを区別しておく。
練習問題 0 / 2問 正解

問1　ソフトウェアの品質特性のうち、別の機種やOSなどの環境に移しやすい度合いを表すものはどれか。

移植性は別の環境に移しやすい度合い。保守性は機能を理解して修正しやすい度合い、使用性は利用者が理解・習得・使用しやすい度合い、効率性は少ない資源で効率よく処理する能力。

問2　ソフトウェアの品質特性のうち、利用者が理解し、習得し、使用しやすい度合いを表すものはどれか。

使用性は使いやすさの度合い。機能性は必要な機能を備えている度合い、信頼性は要求された機能を維持して動作し続ける能力(壊れにくさ)、効率性は少ない資源で効率よく処理する能力。

2OSの役割と基本機能

OS(オペレーティングシステム)は、CPUやメモリなどのハードウェア資源を管理し、アプリケーションソフトウェアに共通の実行環境を提供する基本ソフトウェアである。OSの代表的な機能として、資源管理・ジョブ管理・タスク管理がある。

資源管理機能: CPU・メモリ・入出力装置などのハードウェア資源を複数のプログラムに配分する
ジョブ管理: 利用者が依頼した一連の処理(ジョブ)を、投入から終了まで一括して管理する
タスク管理(プロセス管理): 実行中の個々のプログラム(プロセス)にCPU時間の割り当てなどを制御する
つまずきやすいポイント ジョブ管理は利用者が依頼した一連の処理(ジョブ)を投入から終了まで一括して管理するのに対し、タスク管理(プロセス管理)は実行中の個々のプログラム(プロセス・タスク)にCPU時間を割り当てるなど、より細かい単位を制御する機能である。「ジョブ」と「タスク(プロセス)」の粒度の違いを混同しないこと。
練習問題 0 / 2問 正解

問1　利用者が依頼した一連の処理を、投入から終了まで一括して管理するOSの機能はどれか。

ジョブ管理は、利用者が依頼した一連の処理(ジョブ)を単位として管理する。タスク管理(プロセス管理)は、実行中の個々のプログラムへのCPU時間の割当てなどを制御する。

問2　マルチタスクの説明として、適切なものはどれか。

マルチタスクでは、OSがCPU時間を細かく区切って複数のプログラムに順に割り当てるので、1つのCPUでも複数のプログラムが同時に動いているように見える。エは仮想記憶の説明。

3ファイル管理と仮想記憶

ファイルシステムは、補助記憶装置上のデータをファイル単位で管理し、作成・読み書き・削除などの操作を可能にするOSの機能である。

仮想記憶は、補助記憶装置の一部を主記憶の延長として扱うことで、実際の主記憶容量を超えるサイズのプログラムやデータを扱えるようにする技術である。主記憶に入りきらないデータは、必要に応じて補助記憶装置との間で入れ替えられる。

例題: 主記憶の容量を超えるプログラムを実行できるようにする技術は何か 選択肢: ①仮想記憶 ②キャッシュメモリ ③デフラグメンテーション ④スワッピング
②は処理速度を高速化する仕組み、③は記憶領域の断片化を解消する処理、④は仮想記憶を実現するための入れ替え処理そのものを指す。「容量を超えて扱えるようにする」技術自体を指すのは①仮想記憶。
つまずきやすいポイント 「仮想記憶」は主記憶容量を超えるサイズのプログラムやデータを扱うための仕組み(概念)であり、「スワッピング」はその仕組みを実現するために主記憶と補助記憶の間で実際にデータを入れ替える処理を指す。両者を同じ意味だと思い込まないこと。また、キャッシュメモリは処理速度を高速化するための仕組みであり、記憶容量を拡張する仮想記憶とは目的が異なる。
練習問題 0 / 2問 正解

問1　仮想記憶で、主記憶に入りきらないデータを補助記憶装置との間で入れ替える処理はどれか。

スワッピングは、主記憶のデータを補助記憶装置に書き出し(スワップアウト)、必要なデータを読み込む(スワップイン)処理。デフラグメンテーションは断片化した記憶領域を整理すること、スプーリングは入出力データを一時的に補助記憶装置にためて、CPUの待ちを減らす仕組み。

問2　仮想記憶を使う利点として、適切なものはどれか。

仮想記憶は補助記憶装置の一部を主記憶の延長として扱うので、実際の主記憶より大きなプログラムやデータを扱える。補助記憶装置との入れ替えが起きる分、アクセスはむしろ遅くなることがある。ページフォールトは仮想記憶を使うからこそ起きる。

4周辺ソフトウェア(ミドルウェア・デバイスドライバ・ファームウェア)

ハードウェアとアプリケーションソフトウェアの間には、それぞれ異なる役割を担うソフトウェアが階層的に存在する。ファームウェアは機器に組み込まれてハードウェアの基本動作を制御し、デバイスドライバはOSが個々の周辺機器を制御できるようにし、ミドルウェアはOSとアプリケーションの中間で共通機能を提供する。

種類特徴
デバイスドライバ特定の周辺機器をOSが制御できるようにするため、機器ごとに用意される制御用ソフトウェア
ミドルウェアOSとアプリケーションソフトウェアの中間に位置し、データベース接続など特定の共通機能を提供するソフトウェア
ファームウェアハードウェアの制御のために機器に組み込まれた、基本的な動作を制御するソフトウェア(ROM等に格納されることが多い)
つまずきやすいポイント ファームウェアは機器本体に組み込まれる(ハードウェア寄りの)ソフトウェアであるのに対し、デバイスドライバはOS側から個々のハードウェアを制御するためのソフトウェアである。また、ミドルウェアはOSとアプリケーションの間で共通機能を提供するものであり、特定の周辺機器を制御するデバイスドライバとは役割が異なる。3つの「制御・仲介ソフトウェア」が担う境界の違いを整理して覚える。
練習問題 0 / 2問 正解

問1　特定の周辺機器をOSが制御できるようにするために、機器ごとに用意されるソフトウェアはどれか。

デバイスドライバは、OS側から個々の周辺機器を制御するためのソフトウェア。ファームウェアは機器本体に組み込まれて基本的な動作を制御するソフトウェア、ミドルウェアはOSとアプリケーションの中間で共通機能を提供するソフトウェア。

問2　ソフトウェアをハードウェアに近い順に並べたものとして、適切なものはどれか。

ファームウェアは機器に組み込まれた最もハードウェア寄りのソフトウェア。その上でOS(デバイスドライバを含む)が動き、OSとアプリケーションの間にミドルウェアが位置する。

5ソフトウェアの配布形態

ソフトウェアには、ソースコードの公開範囲や対価の有無によっていくつかの配布形態がある。

配布形態特徴
フリーウェア無償で利用できるソフトウェア(ソースコードは非公開であることが多い)
シェアウェア一定期間または一定機能を無料で試用でき、継続して利用する場合には対価の支払いを求める配布形態
オープンソースソフトウェア(OSS)ソースコードが公開されており、一定のライセンス条件の下で誰でも自由に利用・改変・再配布できるソフトウェア
パッケージソフトウェア汎用的な機能を持ち、パッケージ化されて販売・提供されるソフトウェア
つまずきやすいポイント 「無料かどうか」だけで判断しないこと。フリーウェアとシェアウェアはどちらも無料で使い始められるが、シェアウェアは継続利用に対価が必要になる点で異なる。また、オープンソースソフトウェアの本質は「無料」であることではなく、「ソースコードが公開され、改変・再配布が認められている」ことである。
練習問題 0 / 2問 正解

問1　一定期間または一定の機能を無料で試用でき、使い続ける場合には対価の支払いを求める配布形態はどれか。

シェアウェアは試用後の継続利用に対価が必要。フリーウェアは無償で利用でき、ソースコードは非公開であることが多い。オープンソースソフトウェアはソースコードが公開され、ライセンスの条件の下で利用・改変・再配布できる。

問2　オープンソースソフトウェア(OSS)の説明として、適切なものはどれか。

OSSはソースコードが公開され、ライセンスの条件を守れば利用・改変・再配布できる。著作権は放棄されていない(アは誤り)。OSSの定義では、特定の分野や個人の利用を制限しないので、商用利用もできる(エは誤り)。イはフリーウェアに多い形態。

6タスクの状態遷移とスケジューリング方式

OSのタスク管理では、タスク(プロセス)は「実行可能状態」「実行状態」「待ち状態」の3つの状態を行き来する。CPUを使えるのは実行状態のタスク1つだけで、実行可能状態のタスクの中からどれにCPUを割り当てるかを決めるのがスケジューリングである(この切替えをディスパッチという)。

スケジューリング方式CPUを割り当てる順序
到着順(FCFS)実行可能状態になった順に割り当てる
処理時間順(SPT)処理時間の短いタスクから割り当てる。平均の待ち時間が最も短くなる
優先度順優先度の高いタスクから割り当てる。優先度の高いタスクが来たら実行中のタスクを中断させる(プリエンプション)
ラウンドロビン一定時間(タイムクォンタム)ずつ順番に割り当て、時間が来たら待ち行列の最後尾に回す
つまずきやすいポイント 入出力が終わったタスクは「待ち状態 → 実行可能状態」に移り、CPUの割当てを待つ。すぐに実行状態になるわけではない。また、優先度順だと優先度の低いタスクがいつまでも実行されないことがあり(スタベーション)、待ち時間に応じて優先度を上げるエージングで対策する。
練習問題 0 / 2問 正解

問1　入出力の完了を待っていた待ち状態のタスクは、入出力が完了するとどの状態に移るか。

入出力が終わったタスクは、いったん実行可能状態に戻ってCPUの割当て(ディスパッチ)を待つ。待ち状態から直接、実行状態に移ることはない。

問2　一定時間(タイムクォンタム)ずつ順番にCPUを割り当て、時間が来たら待ち行列の最後尾に回すスケジューリング方式はどれか。

ラウンドロビンは、各タスクに一定時間ずつ順番にCPUを割り当てる。到着順は実行可能になった順、処理時間順は処理時間の短い順(平均待ち時間が最も短くなる)、優先度順は優先度の高い順に割り当てる。

7ページング方式とページ置換アルゴリズム

仮想記憶を実現する代表的な方式がページング方式である。プログラムを一定の大きさの「ページ」に分け、必要なページだけを主記憶に読み込む(ページイン)。参照したページが主記憶にないことをページフォールトといい、このとき主記憶に空きがなければ、どれか1つのページを補助記憶に追い出す(ページアウト)。どのページを追い出すかを決めるのがページ置換アルゴリズムである。

アルゴリズム追い出すページ
FIFO主記憶に最も早く読み込まれたページ
LRU最後に参照されてから最も長い時間がたったページ
LFU参照された回数が最も少ないページ
例題: ページ枠が3つ、ページを 1, 2, 3, 1, 4 の順に参照する(LRU) 1, 2, 3 を読み込んで枠がいっぱいになる → 1 を参照(主記憶にある) → 4 を参照するとページフォールト。最後に参照されてから最も時間がたっているのは 2(1は直前に参照されている)なので、2を追い出して4を読み込む。
FIFOなら、最も早く読み込まれた 1 を追い出す。
つまずきやすいポイント FIFOは「読み込んだ順」、LRUは「参照した順」で判断する。途中で再参照されたページがあると、両者で追い出すページが変わる。また、主記憶が足りずページインとページアウトが頻発し、処理がほとんど進まなくなる状態をスラッシングという。
練習問題 0 / 2問 正解

問1　ページ枠が3つの主記憶で、ページを 3, 1, 2, 3, 4 の順に参照する。ページ置換アルゴリズムがLRUのとき、ページ4を参照したときに追い出されるページはどれか。

ページ4を参照する時点で、最後に参照された時刻は 1 が2番目、2 が3番目、3 が4番目(再参照されている)。最後に参照されてから最も長い時間がたったページ 1 が追い出される。

問2　ページ枠が3つの主記憶で、ページを 3, 1, 2, 3, 4 の順に参照する。ページ置換アルゴリズムがFIFOのとき、ページ4を参照したときに追い出されるページはどれか。

FIFOは主記憶に読み込まれた順で判断するので、最初に読み込まれた 3 が追い出される。途中で 3 が再参照されていても、FIFOでは考慮しない(LRUなら 1 が追い出される)。ページ枠はいっぱいなので、何かを追い出す必要がある。

8OSSのライセンス

オープンソースソフトウェア(OSS)はライセンスの条件のもとで自由に利用・改変・再配布できる。条件は、改変したソフトウェアのソースコードも公開しなければならないかどうかで大きく分かれる。

ライセンス特徴
GPL改変・再配布したソフトウェアもGPLで公開し、ソースコードを開示しなければならない(コピーレフト)
LGPLGPLを緩めたもの。ライブラリとして利用するだけなら、利用側のソースコードの公開は求められない
BSDライセンス・MITライセンス・Apacheライセンス著作権表示などを残せば、改変したソフトウェアのソースコードを公開しなくてよい(商用ソフトに組み込みやすい)
つまずきやすいポイント OSSでも著作権は放棄されておらず、ライセンスの条件を守る必要がある。また、OSSの定義では「特定の分野・個人の利用を制限しない」「有償での販売も妨げない」とされており、「商用利用を禁止できる」「無償でなければならない」という選択肢は誤りである。
練習問題 0 / 2問 正解

問1　GPLのように、改変・再配布したソフトウェアにも同じライセンスを適用し、ソースコードの開示を求める考え方はどれか。

コピーレフトは、改変したソフトウェアも同じ条件で公開させることで、自由に利用できる状態を保つ考え方。パブリックドメインは著作権が放棄された(または消滅した)状態。

問2　MITライセンスのOSSを改変して、自社の製品に組み込んで販売したい。適切なものはどれか。

MITライセンスやBSDライセンスは、著作権表示などを残せば、改変したソフトウェアのソースコードを公開しなくてよい。アはGPL(コピーレフト)の条件。OSSでも著作権は放棄されていないので、ライセンスの条件(著作権表示など)は守る必要がある。
