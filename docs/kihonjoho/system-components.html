システム構成要素のまとめ

デュアル・デュプレックスなどの高信頼化構成、MTBF・MTTRと稼働率の計算、クラスタリング・負荷分散などシステムの可用性を高める構成、信頼性設計の考え方、クラウドサービスの分類、性能評価の指標、仮想化など、システム構成要素で問われる要点を図解しています。読み終えたら下部から問題を解いて定着させましょう。

1システムの処理能力向上:スケールアップとスケールアウト

システムの処理能力(スループット)を高める方法は大きく2つに分けられる。1台あたりの性能を強化する方法と、台数を増やす方法である。

方式別名内容特徴
スケールアップ垂直拡張サーバ自体のCPU・メモリなどのハードウェア性能を強化する構成台数は変わらず管理しやすいが、性能向上には上限がある
スケールアウト水平拡張サーバの台数を増やしてシステム全体の処理能力を高める理論上は台数に応じて性能を伸ばせるが、負荷分散の仕組みが別途必要になる
例題: 台数を増やした場合の処理時間 1台で実行すると60分かかる処理を、性能が同じコンピュータ3台で均等に分散して並列実行する(分散に伴うオーバーヘッドは無視する)。処理時間は台数に反比例するため、60分 ÷ 3台 = 20分となる。
つまずきやすいポイント 「スケールアップ」と「スケールアウト」は名前が紛らわしい。性能を高く「アップ」させるのが1台の強化、規模を外へ「アウト(広げる)」のが台数増加、とイメージで区別するとよい。また実際には分散処理のオーバーヘッドがあるため、台数を増やしても必ずしも台数倍の性能向上にはならない点にも注意する。
練習問題 0 / 2問 正解

問1　サーバの台数を増やして、システム全体の処理能力を高める方法はどれか。

スケールアウト(水平拡張)は台数を増やす方法。スケールアップ(垂直拡張)は1台のCPUやメモリなどの性能を強化する方法。フェイルオーバーは障害時に待機系へ処理を引き継ぐ仕組み、ライブマイグレーションは稼働中の仮想マシンを別の物理サーバへ移す技術。

問2　1台で実行すると90分かかる処理を、同じ性能のコンピュータ3台に均等に分散して並列に実行する。分散に伴うオーバーヘッドを無視すると、処理時間は何分か。

処理を3台で均等に分けるので、1台あたりの処理量は3分の1になり、90 ÷ 3 = 30分。実際には処理の分割や結果の集約にオーバーヘッドがかかるため、台数に比例して速くなるとは限らない。

2高信頼化構成(デュアル・デュプレックス)とMTBF・MTTR

システムの信頼性を高める代表的な構成として、デュアルシステムとデュプレックスシステムがある。両者は名称が似ているため、構成の違いを図でイメージして区別するとよい。

指標意味
MTBF(平均故障間隔)故障してから次に故障するまでの平均動作時間。大きいほど故障しにくい
MTTR(平均修理時間)故障してから修理・復旧が完了するまでの平均時間。小さいほど早く復旧する
稼働率の求め方 稼働率 = MTBF ÷ (MTBF + MTTR)
例題: MTBF270時間、MTTR30時間のシステムの稼働率 稼働率 = 270 ÷ (270 + 30) = 270 ÷ 300 = 0.9 = 90%
つまずきやすいポイント MTBF(動いている時間の平均=長いほど良い)とMTTR(直している時間の平均=短いほど良い)を取り違えない。またデュアルシステム(2系統とも稼働して相互照合)とデュプレックスシステム(主系のみ稼働し従系は待機)の違いを混同しない。
練習問題 0 / 2問 正解

問1　MTBFが380時間、MTTRが20時間のシステムの稼働率はどれか。

稼働率 = MTBF ÷ (MTBF + MTTR) = 380 ÷ (380 + 20) = 0.95。アは MTTR ÷ (MTBF + MTTR) で、稼働していない割合。イとウは MTBF から MTTR を引いてしまった誤りで、それぞれ 360 ÷ 400、360 ÷ 380 の値。

問2　デュプレックスシステムの説明として、適切なものはどれか。

デュプレックスシステムは主系と従系(待機系)からなり、障害時に従系へ切り替える。アはデュアルシステムの説明。イはスケールアップ、エは負荷分散(ロードバランシング)。

3可用性を高めるシステム構成と稼働率の計算

システムの一部に障害が発生しても全体としてサービスを提供し続けられるようにする(可用性を高める)ため、複数の機器を組み合わせる構成が広く使われる。稼働率(前節の MTBF ÷ (MTBF + MTTR))はシステムがどれだけ正常に稼働しているかを表す指標であり、複数の装置を組み合わせた場合は、装置の接続の仕方(直列か並列か)によって計算方法が異なる。

用語説明
クラスタリング同一の機能を持つ複数のコンピュータを連携させ、1台に障害が発生しても他のコンピュータが処理を引き継ぐことで可用性や処理性能を高める構成
負荷分散(ロードバランシング)複数のサーバに処理要求を振り分けることで、特定のサーバへの負荷集中を防ぎ、システム全体の性能や可用性を高める技術
フェイルオーバー稼働中のシステム(主系)に障害が発生した際、自動的に予備の系統(待機系)へ処理を引き継がせる仕組み
直列システムの稼働率 複数の装置を直列に接続した構成では、すべての装置が稼働していないとシステム全体は稼働しない。
稼働率 = A₁ × A₂ × …
並列システムの稼働率 複数の装置を並列に接続した構成(クラスタリングなどの冗長構成に相当)では、少なくとも1台が稼働していればシステムは稼働する。
稼働率 = 1 - (1-A₁) × (1-A₂) × …
例題: 直列システムの稼働率 稼働率0.9の装置Aと稼働率0.8の装置Bを直列に接続したシステムの稼働率は、0.9 × 0.8 = 0.72となる。
例題: 並列(冗長)システムの稼働率 稼働率0.9の装置を2台並列に接続し、どちらか一方が稼働していればよい構成の稼働率は、1 - (1-0.9) × (1-0.9) = 1 - 0.1 × 0.1 = 1 - 0.01 = 0.99となる。クラスタリングなどの冗長化によって可用性が高まることが数値からも確認できる。
例題: 並列と直列を組み合わせた場合 稼働率0.9の装置A・Bを並列に接続した部分(稼働率0.99、上の例題より)の後段に、稼働率0.95の装置Cを直列に接続する。システム全体の稼働率は、0.99 × 0.95 = 0.9405となる。冗長化した部分と単一の部分が混在する構成では、それぞれの稼働率を求めたうえで最後に掛け合わせる。
つまずきやすいポイント 直列と並列の式を混同しやすい。直列は「両方とも必要」なのでそのまま稼働率を掛け算する。並列は「どちらか一方でよい」ので、まず「両方とも故障している確率」(1-A₁)×(1-A₂)を求め、それを1から引く。並列(冗長)構成の稼働率は、必ず個々の装置単体の稼働率より高くなる。
練習問題 0 / 2問 正解

問1　稼働率0.9の装置Aと、稼働率0.95の装置Bを直列に接続したシステムの稼働率はどれか。

直列はすべての装置が稼働している必要があるので、0.9 × 0.95 = 0.855。アは並列に接続した場合(1 − 0.1 × 0.05)、ウは2つの稼働率の平均。直列にすると、システム全体の稼働率は最も低い装置(0.9)よりもさらに低くなる。

問2　稼働率0.8の装置を2台並列に接続し、どちらか一方が稼働していればよいシステムの稼働率はどれか。

並列は「両方とも止まっている」場合だけ停止するので、1 − (1 − 0.8) × (1 − 0.8) = 1 − 0.04 = 0.96。アは直列に接続した場合(0.8 × 0.8)。並列にすると、1台のとき(0.8)より稼働率が高くなる。

4信頼性設計の考え方(フェイルセーフ・フールプルーフ・フォールトトレランス)

障害や誤操作にどう備えるかを表す設計思想の用語は、名前が似ていて混同しやすい。「対象が装置の故障か、利用者の誤操作か」「障害時に安全に止めるのか、動かし続けるのか」という軸で整理するとよい。

用語考え方具体例
フェイルセーフ障害が発生した場合でも、被害を最小限に抑えられるよう、あらかじめ安全な状態に制御しておく信号機は故障すると全方向が赤(停止)になる
フェイルソフト(縮退運転)障害が発生した場合、機能の一部を停止・制限してでもシステム全体の運転を継続する一部のエンジンが故障しても残りのエンジンで飛行を続ける航空機
フォールトトレランスシステムの構成要素の一部に障害が発生しても、全体としては正常な処理を継続できるようにする(多重化などで実現)装置を二重化したシステム
フールプルーフ利用者が誤った操作をしても、システムに重大な影響が及ばないように設計しておくふたを閉めないと動作しない電子レンジ
フェイルセーフ: 安全側に停止させる
フェイルソフト: 機能を縮小し継続
フォールトトレランス: 多重化で継続稼働
フールプルーフ: 誤操作を無害化
つまずきやすいポイント フェイルセーフは「障害時に安全に止める」考え方であるのに対し、フェイルソフトやフォールトトレランスは「障害があっても動かし続ける」考え方であり、方向性が逆である点に注意する。また、フールプルーフだけは対象が「利用者の誤操作」であり、他の3つ(装置の故障が対象)とは前提が異なる。
練習問題 0 / 2問 正解

問1　利用者が誤った操作をしても、システムに重大な影響が及ばないように設計しておく考え方はどれか。

フールプルーフは「誤操作を無害化する」考え方で、ふたを閉めないと動かない電子レンジなどが例。フェイルセーフは障害時に安全な状態に止める考え方、フェイルソフトは機能を縮小して運転を続ける考え方、フォールトトレランスは多重化などで障害があっても正常な処理を続ける考え方。

問2　障害が発生したとき、機能の一部を停止・制限してでも、システム全体の運転を継続する考え方はどれか。

フェイルソフト(縮退運転)は、機能を縮小してでも動かし続ける。フェイルセーフは安全側に止める考え方で、動かし続けることは目的にしない。フォールトトレランスは、障害があっても機能を落とさずに正常な処理を続けることを目指す。

5システムの運用形態(データセンタ・シンクライアント)

情報システムでは、機器をどこに設置するか、また端末側にどこまでの機能を持たせるかという観点でも構成が工夫される。

用語説明
データセンタサーバやネットワーク機器などを一か所に集約し、電源・空調・セキュリティなどの設備を整えて集中管理する施設
シンクライアントシステムクライアント端末には必要最小限の機能(画面表示・入力受付など)のみを持たせ、データ処理やアプリケーションの実行はサーバ側に集約するシステム構成
つまずきやすいポイント シンクライアントは単なる「機能の少ない軽量端末」ではなく、データをサーバ側に集約することで情報漏えい対策や運用管理の一元化に有効という点とセットで問われることが多い。
練習問題 0 / 2問 正解

問1　クライアント端末には画面表示や入力の受付など必要最小限の機能だけを持たせ、データ処理やアプリケーションの実行はサーバ側に集約するシステムはどれか。

シンクライアントシステムは、処理とデータをサーバ側に集約する。データセンタはサーバやネットワーク機器を集約して集中管理する施設。スタンドアロンはネットワークにつながず単独で使う形態、ピアツーピアは端末どうしが対等に直接通信する形態。

問2　シンクライアントシステムを導入する利点として、適切なものはどれか。

シンクライアントはデータをサーバ側に集約するので、情報漏えい対策や運用管理の一元化に役立つ。処理はサーバで行うため、ネットワークが切れると業務を続けにくく(アは誤り)、サーバの負荷は大きくなる(ウは誤り)。端末は最小限の機能でよい(エは誤り)。

6クラウドサービスの提供形態(SaaS・PaaS・IaaS)

クラウドサービスは、提供者がどこまでの範囲を用意し、利用者がどこから先を用意するかによって、主に3つの形態に分類される。

分類正式名称提供される範囲具体例
SaaSSoftware as a Serviceソフトウェアの機能そのものWebメール、オンラインオフィスソフト
PaaSPlatform as a Serviceアプリケーションの実行環境(OS・ミドルウェアなど)アプリケーションの開発・実行基盤
IaaSInfrastructure as a Serviceサーバ・ストレージ・ネットワークなどのインフラ基盤仮想サーバ、クラウドストレージ
つまずきやすいポイント IaaSは基盤(ハードウェア相当)まで、PaaSは実行環境(OS・ミドルウェア)まで、SaaSはソフトウェアそのものまでを提供する、というように「提供者が管理する範囲の広さ」で整理すると区別しやすい。IaaS→PaaS→SaaSの順に、利用者が自分で構築・管理すべき範囲は狭くなっていく。
練習問題 0 / 2問 正解

問1　OSやミドルウェアなど、アプリケーションの実行環境をサービスとして提供するクラウドサービスの形態はどれか。

PaaS(Platform as a Service)は実行環境まで提供し、利用者は自分のアプリケーションを動かす。IaaSはサーバ・ストレージなどのインフラ基盤まで、SaaSはソフトウェアの機能そのものまでを提供する。ハウジングは利用者の機器を事業者の施設に設置するサービス。

問2　利用者がOSを選んでインストールし、その上のミドルウェアやアプリケーションも自分で管理するクラウドサービスの形態はどれか。

IaaSでは提供者が仮想サーバなどのインフラ基盤を用意し、OSから上は利用者が用意・管理する。IaaS → PaaS → SaaS の順に、提供者が管理する範囲が広がり、利用者が用意する範囲は狭くなる。Webメールは SaaS の例。

7システムの性能評価(レスポンスタイム・ターンアラウンドタイム・ベンチマーク)

システムの性能は、「1件の処理にどれだけ時間がかかるか」と「一定時間にどれだけ処理できるか」の2つの観点で評価する。

指標意味主に使う処理形態
レスポンスタイム(応答時間)要求の入力が終わってから、最初の応答が返ってくるまでの時間オンライン処理
ターンアラウンドタイムジョブを投入してから、処理結果がすべて出力されるまでの時間バッチ処理
スループット単位時間あたりに処理できる仕事の量(件数)処理形態を問わない

性能を評価・比較するため、標準的なプログラムを実際に動かして処理時間を測ることをベンチマークテストという(SPECやTPCなどの標準ベンチマークがある)。また、処理件数の増加に対して、将来どれだけの処理能力が必要になるかを見積もることをキャパシティプランニングという。

例題: ターンアラウンドタイムの内訳 ジョブの入力に2秒、CPU処理に5秒、結果の出力に3秒かかる場合、ターンアラウンドタイムは 2 + 5 + 3 = 10秒。一方レスポンスタイムは、入力完了から最初の出力が始まるまでの時間なので、入力時間と出力時間の大部分を含まない。
つまずきやすいポイント レスポンスタイムは「応答が返り始めるまで」、ターンアラウンドタイムは「結果がすべて出終わるまで」。また、レスポンスタイムが短いことと、スループットが高いことは別の話である(1件が速くても同時に多くはさばけない場合がある)。
練習問題 0 / 2問 正解

問1　ジョブを投入してから、処理結果がすべて出力されるまでの時間はどれか。

ターンアラウンドタイムは「結果がすべて出終わるまで」の時間で、主にバッチ処理の評価に使う。レスポンスタイムは要求の入力が終わってから最初の応答が返るまでの時間で、主にオンライン処理の評価に使う。

問2　単位時間あたりに処理できる仕事の量(件数)を表す指標はどれか。

スループットは一定時間に処理できる量で、処理形態を問わずに使う。レスポンスタイムとターンアラウンドタイムは1件の処理にかかる時間の指標。MIPSは1秒間に実行できる命令数(百万単位)で、CPUの性能を表す。

8仮想化とコンテナ

仮想化は、1台の物理サーバ上で複数の仮想的なコンピュータ(仮想マシン)を動かす技術である。サーバの台数を減らしてハードウェア資源を有効に使える(サーバ統合)。

用語説明
ハイパーバイザ型ハードウェア上で直接ハイパーバイザ(仮想化ソフト)を動かし、その上で仮想マシンを動かす。ホストOSを介さないので効率がよい
ホスト型ホストOS上で仮想化ソフトを動かし、その上で仮想マシンを動かす。手軽だがホストOSを経由する分オーバーヘッドが大きい
コンテナ型ホストOSのカーネルを共有し、アプリの実行環境だけを分離する。ゲストOSを持たないので軽量で起動が速い
ライブマイグレーション稼働中の仮想マシンを、停止させずに別の物理サーバへ移動させる技術
VDI(デスクトップ仮想化)利用者のデスクトップ環境をサーバ上の仮想マシンで動かし、端末には画面だけを転送する
つまずきやすいポイント 仮想マシンとコンテナの違いは「ゲストOSを持つかどうか」。コンテナはOSを丸ごと持たない分軽いが、ホストOSと異なる種類のOSは動かせない。ライブマイグレーションは「止めずに移す」点が特徴である。
練習問題 0 / 2問 正解

問1　ホストOSのカーネルを共有し、アプリケーションの実行環境だけを分離する仮想化の方式はどれか。

コンテナ型はゲストOSを持たないので、軽量で起動が速い。ハイパーバイザ型とホスト型はどちらも仮想マシンごとにゲストOSを持つ(ハイパーバイザ型はホストOSを介さない)。VDIはデスクトップ環境をサーバ上の仮想マシンで動かし、端末に画面だけを転送する仕組み。

問2　稼働中の仮想マシンを、停止させずに別の物理サーバへ移動させる技術はどれか。

ライブマイグレーションを使うと、物理サーバの保守のときもサービスを止めずに済む。フェイルオーバーは障害が起きたときに待機系へ処理を引き継ぐ仕組みで、稼働中の仮想マシンをそのまま移すものではない。
