アルゴリズムとプログラミングのまとめ

ソート・探索アルゴリズムや基本的なデータ構造(スタック・キュー・木構造・2分探索木・ヒープなど)、ハッシュ法、フローチャートの読み方など、アルゴリズムとプログラミングで問われる要点を図解しています。読み終えたら下部から問題を解いて定着させましょう。

1流れ図(フローチャート)の読み方とトレース

フローチャート(流れ図)はアルゴリズムの処理の流れを図形で表したものである。基本情報技術者試験では、フローチャートを読み取り、変数の値を1ステップずつ追跡(トレース)して最終結果を求める問題が頻出する。

記号形状意味
開始・終了楕円処理の開始点・終了点を表す
処理長方形代入や計算などの処理を表す
条件分岐ひし形(菱形)条件によって処理の流れを分岐させる
例題: ループ処理のトレース(合計を求める) x=0, i=1 から開始し、「i≦3」の間 x=x+i, i=i+1 を繰り返す。
i=1: x=0+1=1, i=2
i=2: x=1+2=3, i=3
i=3: x=3+3=6, i=4
i=4は条件を満たさずループ終了。出力される x は 6。
例題: ループ処理のトレース(階乗を求める) x=1, i=1 から開始し、「i≦4」の間 x=x×i, i=i+1 を繰り返す(4の階乗を求める処理)。
i=1: x=1×1=1, i=2
i=2: x=1×2=2, i=3
i=3: x=2×3=6, i=4
i=4: x=6×4=24, i=5
i=5は条件を満たさずループ終了。出力される x は 24。
つまずきやすいポイント ループの継続条件(「i≦3」など)を満たさなくなった時点のiの値では、ループ内の処理は実行されない。境界の値を1つ多く/少なく数えてしまうミスが起きやすいので、面倒でも1ステップずつ値を書き出してトレースするとよい。

2データ型と配列・線形リスト

プログラムでは、扱うデータの種類に応じてデータ型を指定する。また、複数のデータをまとめて扱う際には配列や線形リストといったデータ構造を用いる。

データ型扱う値
整数型小数点を含まない整数(例: 1, -5, 100)
実数型小数点を含む数値(例: 3.14)
文字列型文字の並び(例: "ABC")
論理型真(true)・偽(false)の2値
観点配列線形リスト
格納方法連続した領域に格納各データが次データへのポインタを持つ
要素へのアクセス添字で直接アクセスできる(高速)先頭から順にたどる必要がある
挿入・削除後続要素の移動が必要(低速)ポインタの付け替えのみで済む(高速)
つまずきやすいポイント 配列はランダムアクセスが得意だが挿入・削除は苦手、線形リストはその逆(アクセスは苦手だが挿入・削除は得意)という「得意・不得意が逆」の関係で対比して覚えるとよい。

3スタック・キュー・木構造

データの出し入れの順序に着目したデータ構造として、スタックとキューがある。また、データ同士の親子関係を表現するデータ構造として木構造がある。

データ構造略称出し入れの順序操作名
スタックLIFO後入れ先出し(Last In First Out)push(積む)/pop(取り出す)
キューFIFO先入れ先出し(First In First Out)enqueue(追加)/dequeue(取り出す)
例題: スタックの動作 push(1), push(2), push(3) の順に操作した直後に pop() を実行すると、取り出される値は直前にpushした 3。

二分木は、各節(ノード)が持つ子の数が最大2つに制限された木構造であり、探索や整列などのアルゴリズムで広く利用される。子を持たない末端の節を「葉」と呼ぶ。

つまずきやすいポイント スタック(LIFO)とキュー(FIFO)は取り出す順序が逆であるため混同しやすい。「積み重ねた本は上から取る(スタック)」「行列は先頭の人から進む(キュー)」のように身近な例と結びつけて覚えるとよい。

4探索・整列アルゴリズムと計算量(オーダー記法)

アルゴリズムの効率、すなわちデータ量nに対して処理時間がどのように増えるかを表す指標をオーダー記法(O記法)と呼ぶ。データ量が大きくなるほど、O(1)に近いアルゴリズムほど高速である。

オーダー記法(O記法)の大小関係 O(1) < O(log n) < O(n) < O(n log n) < O(n²)　(左ほどデータ量nが増えたときの計算時間の増加が緩やか=高速)
探索アルゴリズム前提条件最悪計算量特徴
線形探索特になし(未整列でもよい)O(n)先頭から順に1件ずつ確認する
二分探索データが整列済みであることO(log n)探索範囲を毎回半分に絞り込む
例題: 二分探索のトレース 整列済み配列 [3, 7, 12, 18, 24, 31, 45, 52] から 24 を探す。
①中央値18と比較→24は18より大きいので右半分[24,31,45,52]
②中央値31と比較→24は31より小さいので左側[24]
③24と比較→一致
合計3回の比較で発見できる(線形探索なら最悪8回かかる)。
整列アルゴリズム平均計算量最悪計算量特徴
バブルソートO(n²)O(n²)隣り合う要素を比較し、逆順なら交換する操作を繰り返す
選択ソートO(n²)O(n²)未整列部分から最小(または最大)値を探し、先頭と交換する
クイックソートO(n log n)O(n²)基準値(ピボット)を用いてデータを分割しながら整列する
マージソートO(n log n)O(n log n)データを分割してそれぞれ整列し、併合(マージ)する
つまずきやすいポイント 「平均計算量」と「最悪計算量」は区別して覚える。クイックソートは平均O(n log n)と高速だが、ピボットの選び方が悪いと最悪O(n²)になる。同様に線形探索も、目的の値が先頭付近にあれば速いが、最悪(末尾または存在しない場合)はO(n)になる。

5サブルーチンと再帰、プログラムの実行方式

プログラム中で繰り返し利用する処理は、サブルーチン(関数、プロシージャ)としてまとめて定義し、必要な箇所から呼び出すことで、プログラムの再利用性・保守性を高めることができる。サブルーチンがその処理の中で自分自身を呼び出す手法を再帰(再帰呼び出し)と呼び、階乗の計算やフィボナッチ数列の計算などによく用いられる。

例題: 再帰による階乗の計算 fact(3) fact(n) を「n≦1なら1、そうでなければ n×fact(n-1)」と定義する。
fact(3) = 3 × fact(2)
fact(2) = 2 × fact(1)
fact(1) = 1(これ以上自分自身を呼び出さない基底条件)
結果を戻しながら計算すると fact(2)=2×1=2、fact(3)=3×2=6。
つまずきやすいポイント 再帰では「これ以上自分自身を呼び出さずに値を確定させる条件(基底条件、上の例ではn≦1)」を必ず設ける必要がある。基底条件がないと自分自身の呼び出しが終わらず、処理が無限に続いてしまう。
処理方式説明
コンパイラ方式ソースコード全体を事前に機械語(オブジェクトコード)へ一括変換してから実行する
インタプリタ方式ソースコードを1行(1文)ずつ解釈しながら実行する

62分探索木とヒープ

2分木のうち、節の値の並べ方に決まりを持たせたものが2分探索木とヒープである。決まりの違いから、得意な操作が異なる。

構造値の決まり得意な操作
2分探索木左の子孫の値 < 節の値 < 右の子孫の値値の探索。根から大小を比べて左右に進むだけで見つかる
ヒープ親の値 ≧ 子の値(または親 ≦ 子)。兄弟の大小は問わない最大値(最小値)の取り出し。常に根にある。ヒープソートや優先度付きキューに使う
完全2分木最下段以外はすべて埋まり、最下段は左から詰めた2分木配列にすき間なく格納できる(ヒープはこの形で作る)
例題: 2分探索木で40を探す 根の50と比べる → 40 < 50 なので左の30へ → 40 > 30 なので右の40へ → 一致。3回の比較で見つかる。
つまずきやすいポイント 2分探索木を「根 → 左 → 右」ではなく「左 → 節 → 右」の順(中間順)でたどると、値が昇順に並ぶ。また、2分探索木は値が偏って追加されると片側に伸びた形になり、探索の効率が線形探索と同じ O(n) まで落ちる。

7ハッシュ法

ハッシュ法は、キーの値をハッシュ関数で計算して格納位置(アドレス)を直接求める探索方法である。比較を繰り返さずに1回の計算で位置が分かるため、探索の計算量は理想的には O(1) になる。

例題: ハッシュ関数「キー mod 7」で格納位置を求める キー 23 → 23 ÷ 7 = 3 余り 2 → 2番目に格納
キー 30 → 30 ÷ 7 = 4 余り 2 → 同じ2番目になってしまう(衝突)

このように、異なるキーから同じ格納位置が求まることを衝突(コリジョン)と呼び、衝突したキーどうしをシノニムという。衝突したときは、空いている次の位置に格納する(オープンアドレス法)、同じ位置のデータを線形リストでつなぐ(チェイン法)などの方法で対処する。

つまずきやすいポイント ハッシュ法は衝突が多くなるほど探索が遅くなる。また、データの格納位置はキーの大小と無関係になるため、「範囲を指定した検索」や「昇順に並べて取り出す」処理には向かない。
